# 数据库、审计与保留规范

## 1. 公共字段

```sql
id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
tenant_id VARCHAR(64) NOT NULL,
created_by VARCHAR(64) NOT NULL,
updated_by VARCHAR(64) NOT NULL,
created_at DATETIME(3) NOT NULL,
updated_at DATETIME(3) NOT NULL,
deleted_at DATETIME(3) NULL,
version BIGINT UNSIGNED NOT NULL DEFAULT 1
```

外部可见业务号不是主键；表间使用内部 `id` 关联，同时保留业务号方便审计和集成。

## 2. 保留期

| 数据 | 策略 |
| --- | --- |
| 客户、商机及合并/作废历史 | 软删除，业务结束后至少 6 年 |
| 客户操作、沟通、商机阶段日志 | 永久或依组织合规策略更长者 |
| Portal 登录、报告发放、评价、备案 | 永久留痕；文件本体按安全策略归档 |
| 项目进度快照 | 保留最新快照，必要时保留有限历史用于审计 |
| Outbox、幂等记录 | 成功后按运维策略归档；死信不得自动删除 |

## 3. 审计事件

审计表至少包含：

```text
event_id, tenant_id, application_code, module, operation,
resource_type, resource_id, actor_id, actor_name_snapshot,
before_json, after_json, reason, result, request_id,
ip, user_agent, occurred_at
```

敏感字段在 `before_json/after_json` 中仅保存掩码或不可逆摘要。登录失败不能记录提交的密码。

## 4. 必审计操作

- 客户创建、编辑、导入、合并、作废、敏感字段查看和导出；
- 门户账号开通、邀请生成、验证、使用、撤销和重发；
- 商机创建、作废、团队变更、每次阶段调整、外部状态回写；
- 售前申请、审批、指派/改派、取消、工时和重试；
- Portal登录、会话撤销、授权失效、报告申请/回调/下载/冻结、备案提交/解锁、评价和反馈；密码/锁定/MFA审计归平台，Portal不复制改密。

## 5. Migration 交付

每个需求必须提交：up migration、可验证的 down/恢复说明、索引说明、历史数据回填脚本（如有）、大表执行风险和发布顺序。生产禁止运行 GORM AutoMigrate。
