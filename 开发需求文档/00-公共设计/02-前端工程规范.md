# Vue 3 + Vite 前端工程规范

## 1. 技术约束

- 沿用统一前端的 Vue 3 Composition API、`<script setup>`、JavaScript ES Module、Vite 和 Vue Router。
- 沿用模块内原生 `fetch` 客户端；统一附带同源 Cookie、CSRF Token、幂等键，并统一解析 401/403/409/422。不得再引入一套并行请求客户端。
- 当前依赖中没有 TypeScript、Pinia、Axios 或 Element Plus；业务状态使用 Vue `ref/reactive/computed`，跨页面状态优先放 URL 或服务端，不把它们写成已落地依赖。
- API 边界必须显式规范化服务端 DTO，禁止组件根据字段名猜测含义。
- 表单校验前后端双重执行，前端校验不能替代后端规则。

## 2. 模块结构

```text
modules/customer_opportunity/
  api/*.js
  views/CustomerOpportunityView.vue
  styles/customer-opportunity.css
  module.js

modules/customer_portal/
  api/*.js
  components/*.vue
  views/CustomerPortalView.vue
  styles/customer-portal.css
  module.js
```

每个需求文档列出的页面、组件、API 和权限必须落到对应模块；模块通过根 `moduleRegistry.js` 和 Vue Router 注册，不能靠本地目录存在就绕过基础平台的应用目录或会话门禁。

## 3. 路由与授权

- CRM 路由进入前调用 CRM `/auth/me`，Portal 路由进入前调用 Portal 会话接口；两类业务会话不可互相替代。
- 路由负责系统级会话门禁，按钮和分区按各后端返回的精确 permission 失败关闭。
- 直接输入 URL 也走守卫；403 显示无权限页，401 跳本系统登录入口。
- 数据范围不在前端实现，前端不得携带可扩大范围的 owner/tenant 覆盖参数。

## 4. 列表与表单

- 筛选条件同步 URL query，刷新可恢复；分页默认 20，允许 20/50/100。
- 列表请求支持取消，快速筛选时取消旧请求；排序字段使用后端白名单。
- 表单区分 create/edit/detail schema；提交期间禁用重复点击并传 Idempotency-Key。
- 409 版本冲突提示“数据已被他人修改”，允许刷新后重新编辑，禁止静默覆盖。
- 离开脏表单前二次确认；成功后以服务端返回数据刷新。

## 5. 安全

- Token 不写 localStorage/sessionStorage；不把 Secret、初始密码、完整敏感信息写日志或埋点。
- 富文本使用白名单 sanitizer；外链增加协议校验和 `rel=noopener`。
- 下载文件名和 Content-Type 以服务端响应为准，防止脚本文件伪装。
- 手机号、税号、银行账户等默认脱敏；仅服务端确认有权限时显示明文。

## 6. 可访问性和交互

- 表单控件有 label、错误说明和键盘焦点；弹窗关闭后焦点返回触发元素。
- 状态不能只用颜色表达，同时显示文本或图标。
- Loading、空数据、无权限、依赖失败、部分成功均有独立状态。
- 本期桌面端最小宽度 1280px；不验收移动端和响应式，但不能阻断浏览器缩放。

## 7. 测试

- 当前自动化使用 `node:test` 覆盖 API 客户端、规范化函数、路由/权限边界及关键源码契约，并由 `npm run build` 验证 Vue/Vite 集成。
- 组件挂载测试、真实浏览器 E2E 和每个 P0 的越权/失败链路仍是上线门禁，当前不能因源码契约测试通过而视为已完成。
- Mock 必须与真实后端路由和 DTO 对齐；禁止在组件内硬编码演示数据。
