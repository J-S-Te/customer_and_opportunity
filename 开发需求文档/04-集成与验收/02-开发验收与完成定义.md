# 开发验收与完成定义（Definition of Done）

## 1. 单需求完成条件

每个需求只有同时满足以下内容才可标记完成：

- 业务规则、状态机、权限和数据范围通过产品/架构评审；
- up migration、恢复方案、GORM Model、Repository、Service、Handler 和 routes 完成；
- OpenAPI 定义、错误码、示例和幂等规则完成；
- Vue 页面、组件、路由守卫、异常/空态和权限按钮完成；
- 单元、集成、契约和至少一条 E2E 主链路通过；
- 越权、IDOR、注入/XSS、敏感字段和审计检查通过；
- 指标、结构化日志、告警、健康检查和运维说明完成；
- 与原型差异已记录，不能以原型 demo 逻辑替代生产规则。

## 2. 质量门禁

| 项目 | 门禁 |
| --- | --- |
| Go | `go test ./...`、`go vet ./...`、静态检查无高危 |
| Vue | typecheck、lint、unit、build 全通过 |
| 覆盖 | 核心 Service 建议 ≥80%；状态机/权限关键分支 100% |
| API | OpenAPI lint 和破坏性变更检查通过 |
| DB | migration 在空库、升级库、回滚/恢复场景验证 |
| 安全 | P0/P1 高危缺陷为 0，依赖无未豁免高危漏洞 |
| 性能 | 100 并发读 P95≤2s；核心写达到约定 200 TPS 基线 |
| 集成 | 幂等、重试、乱序、超时、死信和对账均验证 |

## 3. P0 端到端主链路

1. CRM OIDC 登录 → 创建客户 → 查重/查询 → 创建商机 → 任意阶段调整立即生效。
2. 外部中标无合同 → 已签约 + 待关联合同；外部落标无原因 → 失败 + 待补原因。
3. CRM 预置基础平台外部用户和 Portal 角色 → 生成邀请 → Portal 校验邀请 → 基础平台 OIDC 登录 → sub 匹配后消费邀请 → 客户隔离。
4. 商机发起 TS → 两级审批 → 多人指派 → 部分执行人登记后保持执行中 → 所有当前执行人均登记后自动完成 → PMS 异步成功/失败重试。
5. Portal 查看项目快照 → 申请报告 → 下游审批回调 → 加密水印 → 72h 受控下载。

## 4. 上线前接入验收

CRM 和 Portal 分别完成 Application/Environment/LoginTarget/OAuth Client 登记；前端承载已确定为统一 Vue 构建中的两个独立业务模块，仍须逐系统确认 public URL、path_prefix、upstream、callback、Cookie Path、Docker 网络和 `/healthz`。

CRM 与 Portal 均必须完成 OIDC PKCE、本地会话、授权目录和后端鉴权。Portal 还必须验证 `sub ↔ customer_id` 映射，拒绝无映射、停用映射和邀请用户不匹配的 OIDC 回调。

## 5. 发布与回滚

- 先执行兼容性 migration，再发布能兼容新旧字段的后端，最后发布前端和异步消费者。
- 枚举/状态扩展先让消费者兼容未知值，再发布生产者。
- 回滚不能删除已产生业务数据；使用特性开关停止新入口，旧版本必须能读取新数据或提供前滚修复。
- 日常发布使用 update/CI-CD，不重新 onboard，不删除 Application 或 OAuth Client。
