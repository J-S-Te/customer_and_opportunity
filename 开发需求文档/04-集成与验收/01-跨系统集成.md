# 跨系统集成规格

## 1. 通用契约

- 同步接口使用服务身份 OAuth Client Credentials；每种用途独立 Client 和最小 scope。
- 基础平台 `/oauth2/token` 使用 `client_secret_basic`，表单只传 `grant_type=client_credentials` 和 `scope`。当前平台对 application Token 使用部署级统一 audience；接收系统必须按同一平台配置严格校验 `aud`，不能假设 token 请求支持按目标系统选择 audience。写调用另带 RFC3339Nano 时间戳和一次性随机 nonce 防重放。
- 请求/响应使用统一外层结构和 `request_id`；时间 ISO 8601 UTC，金额/小时用字符串 decimal 避免精度损失。
- 写接口/消息均需业务幂等键；签名或 Token 不能只依赖 IP 白名单。
- HTTP 连接/请求超时、有限重试、熔断、指标和脱敏日志必须配置。
- 本地业务事务通过 outbox 发布；消费端保存 inbox/idempotency 记录。

## 3. 关键修订

- G 中标缺 contractId：CRM 仍直接 `已签约/CLOSED`，`terminal_pending_type=CONTRACT`。
- G 落标缺 lostReason：CRM 仍直接 `失败/CLOSED`，`terminal_pending_type=LOST_REASON`。
- 商机人工阶段调整无需审批；外部回传也不创建商机审批。
- K 正式幂等键使用 worklogId，解决同一人同日多笔工时冲突；若 PMS 暂不支持，需要联调迁移方案，不能丢第二笔。
- Portal 外部客户采用基础平台 OIDC，不传输初始口令，不保留 Portal 本地密码或独立 portal-jwt。
- N 拆为 verify + consume：verify 返回预期 sub；Portal 完成 OIDC 回调并确认实际 sub 匹配后 consume，避免登录失败或账号不匹配时提前作废邀请。
- D/E/F 的拥有者是 Portal，不是 CRM；CRM 不保存 Portal 报告文件。

## 4. 接口最小权限

| 调用方 | audience | scope |
| --- | --- | --- |
| 报价投标系统 | crm | opportunity.status.write / opportunity.summary.read |
| CRM | contract | contract.summary.read / opportunity.signed.write / contract.opportunity_signed_count.read（独立 Client） |
| CRM | pms | technician.read / presale.worklog.write |
| CRM | platform-management | external_user.provision / application_role.assign |
| CRM | portal | portal.identity_mapping.provision |
| Portal | crm | portal.invite.verify / customer.summary.read |
| Portal 浏览器/后端 | platform-oidc | openid profile + Portal 应用 roles/permissions |
| Portal | project-service | project.snapshot.read / report.request.write |
| 项目服务 | portal | report.callback.write |
| CRM | portal | portal.project_history.read |

`portal.project_history.read` 仅允许读取 Portal 本地持久化的客户项目摘要。调用使用独立 Client Credentials、平台部署级 application-token audience、`X-Integration-Timestamp` 和单次 nonce；Portal 从签名 Token 取得 tenant，只接受正整数 customerId 和严格分页。响应必须返回 `source_updated_at/synced_at/sync_last_success_at/stale/staleness_seconds`：`source_updated_at` 是项目源内容版本时间，`synced_at` 是该快照行因内容变化而落库的时间，`sync_last_success_at` 是 `tenant + customer` 同步链路最后一次完整成功时间；`stale/staleness_seconds` 只基于 `sync_last_success_at`，不得用长期未变化的快照行时间误判，也不得表述为项目服务实时状态。从未完整成功同步时 `sync_last_success_at` 和 `staleness_seconds` 均为 `null`、`stale=true`。响应禁止返回 Portal 账号、项目经理内部标识、团队联系方式或原始源版本。

### 4.1 商机已签约合同数量

- CRM 使用独立 Client Credentials 和唯一 scope `contract.opportunity_signed_count.read` 调用 `POST /contract_management/internal/opportunity-contract-counts/query`，请求同时携带 Bearer Token、RFC3339Nano `X-Integration-Timestamp`、一次性 `X-Integration-Nonce` 和可选链路 `X-Request-ID`。
- 请求体为 `{ "opportunity_ids": ["1", "2"] }`；列表最多 100 个，看板最多 1000 个，详情固定 1 个。合同系统按 Token 中的 tenant 与 `opportunity_id` 联合定位，并负责“签署完成”的业务定义与计数。
- 成功响应使用统一 envelope：`data.items` 中每项为 `{ "opportunity_id": "1", "signed_contract_count": 2 }`。响应必须恰好覆盖全部请求 ID，不允许重复、缺失或额外 ID，数量必须为非负整数。
- CRM 在一次列表或看板请求中只发起一次批量调用，不在本地数据库持久化或缓存数量。正常无合同返回 `0`；未启用、超时、认证失败、非法响应或合同服务错误均返回 `signed_contract_count: null`，且不影响商机核心数据。

## 5. 失败与补偿

- 同步读失败：返回受控依赖错误；可用缓存的只读场景展示最后更新时间。
- 同步写失败：不伪造成功；本地若已产生业务状态，写补偿/重试任务。
- 异步失败：重试后死信，业务状态不倒退；提供人工重试和对账。
- 每日对账：邀请账号映射、投标终态待办、PMS 工时投递、报告请求/回调分别输出差异清单。

## 6. 契约测试

每个流提供 JSON Schema/OpenAPI、成功示例、全部枚举、认证失败、幂等重放、乱序、超时和错误示例。Provider 发布前运行消费者契约；破坏性字段变更必须提升 eventVersion/API 版本。
