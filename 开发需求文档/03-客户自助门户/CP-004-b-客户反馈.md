# CP-004-b 客户反馈

## 1. 目标

提供异议、投诉、建议三类反馈，客户跟踪处理状态；首次响应目标 24 小时，超时自动升级。原型当前未覆盖完整通道，本规格作为开发基准。

## 2. 字段与状态

字段：反馈号、类型、标题、描述、关联项目（可选）、附件、期望联系方式、提交账号。状态：`SUBMITTED → ACCEPTED → PROCESSING → RESOLVED → CLOSED`；可从处理中进入 `NEED_CUSTOMER_INFO`，客户补充后回 PROCESSING；无效反馈 `REJECTED` 必填原因。

24 小时 SLA 从 submitted_at 起算，到第一条有效内部响应停止；系统自动确认不算人工响应。超时生成升级事件，接收管理层站内消息。

## 3. 数据

- `portal_feedbacks(feedback_no,customer_id,account_id,project_id,type,title,description,status,first_response_due_at,first_responded_at,resolved_at,closed_at)`。
- `portal_feedback_messages(feedback_id,sender_type,sender_id,content,visibility,created_at)`；内部备注不能返回客户。
- `portal_feedback_attachments`；病毒扫描通过后可见。
- `portal_feedback_escalations(feedback_id,level,reason,sent_at)`，唯一反馈+级别。

处理端归属哪个内部系统尚未明确；首版 Portal 提供受控管理 API/页面或机器接口，不能只有客户提交没有处理闭环。

## 4. API

客户侧：`POST/GET /api/v1/feedbacks`、`GET /feedbacks/{id}`、`POST /feedbacks/{id}/messages`、`POST /feedbacks/{id}/close`。关闭必须携带 `Idempotency-Key`，先按 Portal 会话证明反馈可见，再按租户全局键校验反馈、账号、动作和载荷摘要；精确重放不重复状态日志或 outbox，同键跨反馈/账号使用固定返回 409。处理侧：`GET /internal/feedbacks`、`POST /internal/feedbacks/{id}/accept|respond|resolve|reject`，必须使用内部角色或机器身份，并遵循同一租户级状态动作键约束。

## 5. 前端

客户反馈列表、创建页、详情会话时间线；明确区分状态和 SLA。确认关闭在页面生命周期为同一反馈复用显式键，仅在服务端确认成功后清除并禁用重复点击。上传附件先显示扫描中。处理端页面若本期交付，必须与客户门户路由/权限分开。

## 6. 验收

- 三类反馈均可提交并获得唯一编号，客户只见自己的反馈。
- 第一条有效响应正确停止 24h 计时；超时只升级一次且可统计。
- 内部备注绝不出现在客户 API；附件扫描失败不可下载。
- 状态迁移、驳回原因和全部消息可审计。
- 关闭响应丢失后同键重试仍返回已关闭时间线，状态日志和 outbox 均只有一份；其他反馈或账号不能用猜测键读取原结果。
- 原型缺失的提交和状态跟踪页面完成后方可验收本需求。
