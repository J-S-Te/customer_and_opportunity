# CP-004-a 服务评价

## 1. 规则

客户对已完成或允许评价的项目提交一次服务评价：专业能力、响应速度、报告质量、服务态度四项 1～5 星，评语可选。修改窗口是否开放未定义，首版提交后不可修改；管理员不能代改，只能标记不当内容。

任一维度 ≤2 星或平均分 ≤2 时触发管理层站内提醒。匿名化只针对统计展示，原始评价仍需关联客户/项目以防重复和处理问题，访问权限严格限制。

## 2. 数据

`portal_service_evaluations(evaluation_no,customer_id,project_id,account_id,professional_score,response_score,report_score,attitude_score,average_score,comment,status,submitted_at)`；唯一 `(tenant_id,customer_id,project_id)`。

`portal_evaluation_alerts(evaluation_id,rule_code,status,sent_at)`；聚合报表不得输出小样本可识别组合，最小样本阈值建议 5。

## 3. API

`GET /api/v1/projects/{id}/evaluation-eligibility`、`POST /api/v1/evaluations`、`GET /api/v1/evaluations/{id}`。管理端若后续展示统计使用独立机器接口和权限，不复用客户 API。

提交 Service 校验项目归属、项目状态、唯一约束、分数范围，在事务内写评价、低分 outbox 和审计。

## 4. 前端

四维星级必须有可读数值/标签和键盘操作；提交前展示汇总，成功后只读。低分不在客户端决定是否提醒。

## 5. 验收

- 非本人项目、未完成项目、重复评价、非法分值被后端拒绝。
- 四维平均计算精度一致；低分提醒幂等发送。
- 统计匿名且小样本不泄露评价主体；原始评价永久审计留存。
- XSS 内容被清洗；前端星级可访问。
