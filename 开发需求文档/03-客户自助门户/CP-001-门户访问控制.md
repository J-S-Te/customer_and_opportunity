# CP-001 Portal 基础平台 OIDC 访问控制

## 1. 身份方案

Portal 是独立子系统，外部客户统一采用基础平台 OIDC Authorization Code Flow + PKCE S256。Portal 不提供自注册、不保存或校验密码、不签发独立身份 Token；仅维护 OIDC `sub` 与 CRM `customer_id` 的业务映射，并建立自己的服务端会话。

Portal 必须有独立 Application、Environment、LoginTarget 和 confidential Web OIDC Client。浏览器 Client、授权目录同步 Client、CRM 调用 Client和审计 Client不得混用。

## 2. 账号预置与邀请登录

1. CRM 通过基础平台受控接口预置外部用户并分配 `portal_customer` 角色，再调用 Portal 建立 PENDING 映射。
2. 客户从 CRM 24 小时邀请链接进入 Portal `/activate?token=...`；Portal 服务端调用 CRM verify，获得 expected sub/customer_id，并创建 10 分钟激活上下文。
3. Portal `/auth/login` 生成安全随机 state、nonce、code_verifier 和 PKCE challenge；state 单次消费并绑定激活上下文、原目标路径和浏览器会话。
4. 回调在后端交换 Token，严格校验签名算法、kid、iss、aud、exp、iat、nonce、`token_use=id_token`、tenant_id、roles、permissions、role_config_hash、authz_revision。
5. 邀请登录必须满足 `token.sub == expected sub`；普通后续登录必须存在 ACTIVE `sub ↔ customer_id` 映射。
6. Portal 拒绝未知角色、跨应用权限、不兼容角色目录哈希、无 customer 映射或被禁用映射。
7. 首次邀请回调成功后激活映射并调用 CRM consume，再建立本地会话；后续访问不再需要邀请。

基础平台负责密码设置/找回、登录失败锁定、MFA 和平台账号禁用。Portal 只展示/跳转平台账号安全能力，不复制这些规则。

## 3. 本地会话

- 服务端存储，Cookie 名建议 `customer_portal_session`；`HttpOnly; Secure; SameSite=Lax; Path=<portal_path>`；
- 会话有效期不超过关联 Token，建议最长 15 分钟；绝对有效期和空闲有效期取更短者；
- 定期调用 UserInfo 或要求重新登录，使权限变更、平台账号禁用和角色回收及时生效；
- logout 撤销服务端会话并清 Cookie，可选跳平台 RP-Initiated Logout；
- 写接口校验 CSRF Token 和严格 Origin；Token 不进入 localStorage/sessionStorage；
- 401 跳 `/auth/login`，403 展示无权限，不得循环重定向。

## 4. 数据模型

### `portal_identity_links`

`account_no,platform_user_id,tenant_id,customer_id,contact_id,status(PENDING/ACTIVE/DISABLED),display_name_snapshot,activated_at,disabled_at,last_claims_revision,last_verified_at`。

唯一 `(tenant_id,platform_user_id)`；customer_id 建索引。禁止 `password_hash/force_password_change/failed_count/locked_until` 等本地凭据字段。

### `portal_sessions`

`session_id_hash,platform_user_id,customer_id,authz_revision,role_config_hash,expires_at,absolute_expires_at,last_seen_at,revoked_at,ip_hash,user_agent_hash`。

### `portal_activation_contexts`

`context_id_hash,invite_token_hash,expected_platform_user_id,customer_id,state_hash,nonce_hash,pkce_verifier_cipher,return_path,expires_at,consumed_at`；短期保留并定时清理。

### `portal_auth_events`

记录登录开始、回调成功/失败、sub 不匹配、会话撤销、UserInfo 复核，不记录 Token、授权码、Cookie、Secret 或完整邀请 token。

## 5. 必要端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/internal/accounts/provision` | CRM 机器身份，幂等建立 sub/customer 映射 |
| GET | `/activate` | 接收邀请 token，服务端 verify 后进入 OIDC |
| GET | `/auth/login` | 创建 state/nonce/PKCE 并跳基础平台 |
| GET | `/auth/callback` | 后端换 Token、校验 Claims、建立会话 |
| POST | `/auth/logout` | 撤销本地会话；必须通过同源与 CSRF 校验 |
| GET | `/api/v1/auth/me` | 返回 sub、customer_id、roles、permissions、哈希、修订号、expires_at |
| GET | `/healthz` | 网关健康检查 |

普通 `/auth/login` 无 ACTIVE 映射时，OIDC 回调返回 `PORTAL_IDENTITY_NOT_PROVISIONED`，提示联系客户经理，不自动注册。

## 6. 前端

页面：邀请校验/OIDC 跳转、登录失败、身份未开通、账号不匹配、无权限、会话过期。登录页只有“使用统一身份平台登录”按钮；不出现用户名、密码、忘记密码或 Portal 改密表单。Router 启动调用 `/api/v1/auth/me`，业务请求使用同源 Cookie。

## 7. 权限和数据隔离

基础平台 Claims 决定角色/权限；Portal Service 强制以本地映射的 customer_id 过滤所有项目、报告、备案、评价、反馈、附件和导出。请求参数中的 customerId 不得覆盖会话 customer_id。

## 8. 验收标准

- Authorization Code + PKCE S256、state/nonce 单次消费和全部 Token Claims 校验通过安全测试；
- 错误 state/nonce/issuer/audience/签名/token_use/过期 Token 均被拒绝；
- 邀请 expected sub 与实际登录 sub 不一致时拒绝且不消费邀请；
- 无 ACTIVE 映射、无 Portal 角色、跨租户和跨应用权限均拒绝；
- Portal 数据库、代码、日志和前端不存在客户密码、密码哈希、默认口令或独立 portal-jwt；
- 平台账号/角色禁用在约定时限内使 Portal 会话失效；
- 客户 A 无法枚举、查看、下载或修改客户 B 的任何资源。
