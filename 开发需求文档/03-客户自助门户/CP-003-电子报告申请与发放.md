# CP-003 电子报告申请与发放

## 1. 流程

客户选择自己的项目、报告类型、申请原因和接收邮箱提交；Portal 可靠推送项目服务审批；项目经理在下游审批并回调；Portal 校验文件、加密保存、生成 72 小时下载授权并记录下载审计。

## 2. 状态机

`SUBMITTED → APPROVING → APPROVED_PROCESSING → ISSUED`；审批拒绝 `REJECTED`；技术失败 `PROCESSING_FAILED` 可重试。下载授权独立为 `ACTIVE/EXPIRED/FROZEN/REVOKED`。

## 3. 数据

- `portal_report_requests(request_no,project_id,customer_id,report_type,reason,receive_email_cipher,status,downstream_request_id,approval_result,submitted_at,approved_at,issued_at)`。
- `portal_report_files(request_id,object_key_cipher,file_name,mime,size,file_hash,encryption_key_ref,watermark_status,created_at)`；文件使用 AES-256-GCM 信封加密，密钥不入库明文。
- `portal_report_grants(token_hash,request_id,customer_id,account_id,expires_at,status,download_count,risk_state)`；明文 token 只在创建成功响应返回一次，数据库只存高熵 token 的 SHA-256 摘要。
- `portal_report_download_events(request_id,grant_id,account_id,ip_hash,device_hash,event_type,result,reason_code,occurred_at)`，只插入。

## 4. API 与集成

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/customer-portal/api/v1/reports` | 幂等提交，仅本人项目 |
| GET | `/customer-portal/api/v1/reports` | 列表 |
| GET | `/customer-portal/api/v1/reports/{id}` | 详情/审批记录 |
| POST | `/internal/report-callbacks` | 项目服务回调 |
| POST | `/customer-portal/api/v1/reports/{id}/download-grants` | 创建/刷新短效授权 |
| POST | `/customer-portal/api/v1/reports/{id}/downloads` | 校验授权后流式解密下载 |

回调校验机器身份、requestId、fileHash、文件类型/大小和幂等键；服务端从受信 object ref 拉取，不能允许回调提供任意 URL 造成 SSRF。

两个下载 POST 均必须同时通过 Portal HttpOnly Cookie 会话、`report.download`、同源 Origin 和 CSRF 头校验。创建 grant 要求每次人工操作的新 `Idempotency-Key`，并仅一次返回 `grant_id/status/expires_at/download_token`；同 key 重放因无法安全恢复明文 token 而返回 409。流式下载必须把 token 放在 `X-Report-Download-Token`，禁止放入 URL、请求体、`Authorization`、日志或浏览器持久存储。下载返回 `Cache-Control: no-store, private`，且只有实际流字节数和 SHA-256 与可信元数据一致才记为成功。

无效 token（含非法长度）只在当前 tenant/customer/account/report 确认可见后按“账号+报告+小时”有界记录一次拒绝事件，不保存 token 或 token 摘要；不存在和越权报告统一返回 404，不能通过审计依赖状态枚举 ID。数据库文件元数据必须在申请内存缓冲和打开对象 reader 前再次限制为 `0 < size <= 50 MiB`。正式 `OpenVerified` reader 必须在 context 取消后解除阻塞；当前未接可信 reader 时只能返回 503，不能生成占位 PDF。报告申请和 grant 的操作人审计列按 Portal OIDC account/subject 的 128 字节上限设计。

## 5. 水印和异常下载

PDF 水印至少含客户名称、账号掩码、request_no、下载时间和不可预测追踪码。异常规则参数化：短期高频、多个设备/IP、风险 IP；命中时冻结 grant 并站内告警，人工复核后解冻/重发。

风险规则只接受可信网关/GeoIP Provider 的结论；Provider 未配置或调用失败时下载失败关闭。冻结与账号范围站内告警、拒绝审计同事务写入。人工复核使用独立机器 scope `portal.report.risk.manage`，按租户读取告警并提交 `expected_version + Idempotency-Key + reason`：`UNFREEZE` 仅恢复尚未过期且当前不存在其他活动授权的原 grant；`REVOKE_AND_REISSUE` 撤销旧 grant，由客户下次显式点击重新生成一次性授权。复核接口不生成、不返回明文 token，也不能跳过对象读取、病毒扫描、加密、水印或风险检查。

本期通知以站内消息为主；旧用例“邮箱下发”与“本期不接邮件”冲突，开发不发送含文件/明文链接的邮件，仅保存接收邮箱供下游审批语义或后续能力。

## 6. 前端

报告中心含申请表、状态列表、详情时间线、下载/过期/冻结提示。项目选择器只返回当前客户项目；重复提交时明确显示已有申请。

## 7. 验收

- 越权项目不能申请；重复 Idempotency-Key 只创建一个请求。
- 回调重复/乱序不重复发放；文件 hash 不符、类型异常或任意 URL 被拒绝。
- 存储中无明文报告和明文密钥；下载在服务端鉴权并审计。
- 下载授权最长 72h，到期、冻结、撤销和刷新撤销旧 grant 正确；跨账号/客户/报告不可使用。
- 非法长度、错误 token、越权报告和不存在报告不会产生可用于枚举 ID 的响应差异；审计依赖真实失败时安全关闭。
- 水印可追踪，异常下载冻结不影响原申请审计记录。
