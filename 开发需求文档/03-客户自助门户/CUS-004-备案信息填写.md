# CUS-004 等保备案信息填写

## 1. 目标

以 7 步向导完成《等保备案表 2025 版》6 表和定级报告，支持实时校验、自动暂存、生成 PDF、提交锁定和管理员受控解锁。

## 2. 步骤

1. 单位基本情况；2. 定级对象情况；3. 定级情况；4. 新技术应用；5. 提交材料；6. 数据摸底；7. 定级报告。字段 schema 必须版本化为 `filing_form_version=2025.1`，不能只把所有内容存一个无约束 JSON。

## 3. 状态

Portal 本地确认固定为 `DRAFT → WAITING_CONTRACT`，此时只表示不可变快照已经锁定，不表示公安受理。正式提交 Provider 配置后，投递状态为 `WAITING_CONTRACT → SUBMITTING → SUBMITTED`；只有经验证的公安回执与状态在同一事务保存成功才允许进入 `SUBMITTED`。有限重试耗尽进入 `SUBMISSION_FAILED`，由管理员核对后处理。`WAITING_CONTRACT`、`SUBMISSION_FAILED` 和 `SUBMITTED` 可由具有 `filing.unlock` 权限的管理员携理由直接恢复 `DRAFT` 并审计；`SUBMITTING` 期间禁止解锁，避免外部已经受理而本地快照被修改。是否为解锁增加通用审批引擎仍需业务确认。

## 4. 数据模型

- `portal_filings(filing_no,customer_id,project_id_nullable,form_version,status,current_step,completion_pct,submitted_at,locked_at,unlocked_at,unlock_reason)`。
- 六个结构化 section 表或 `portal_filing_sections(filing_id,section_code,schema_version,data_json,validation_status,version)`；对需检索/统计字段单独拆列。
- `portal_filing_materials(filing_id,section_code,object_key,file_name,hash,scan_status)`。
- `portal_filing_matrix(filing_id,matrix_code,row_code,column_code,selected)`，数据库唯一保证每个 matrix_code 仅一个 selected。
- `portal_filing_exports(filing_id,object_key,template_version,generated_at)`。
- `portal_filing_submission_outbox(event_id,submission_id,contract_version,status,retry_count,lease)` 与 `portal_filing_submission_receipts(provider_receipt_id,provider_authority,provider_evidence_cipher,provider_evidence_sha256,received_at)`；回执证据只保存认证加密密文及明文摘要，不接受浏览器提供的回执号。

## 5. API

`POST /api/v1/filings`、`GET /api/v1/filings/{id}`、`PUT /api/v1/filings/{id}/sections/{code}`、`PUT /api/v1/filings/{id}/matrix/{code}`、`POST /api/v1/filings/{id}/validate`、`POST /api/v1/filings/{id}/submit`、`POST /api/v1/filings/{id}/unlock`、`POST /api/v1/filings/{id}/exports`。

暂存接受 section version；提交在事务中锁 filing，执行跨 section 完整校验，生成不可变提交快照。PDF 从提交快照生成，避免后续解锁修改影响已提交版本。

公安提交由独立 provider-neutral Worker 读取不可变快照及全部 `CLEAN` 材料证据，以稳定 `event_id` 调用正式 Provider。正式 2025 全字段、签名、附件传输、回执格式和公安端点尚未签版时，不实现猜测字段的 HTTP 适配器；运行时保持 `WAITING_CONTRACT`，不得伪造成功。

## 6. 前端

`FilingWizard.vue` 动态加载版本化 schema；每步本地校验 + 服务端暂存，显示保存状态。步骤允许跳转但提交必须全量通过。等级矩阵支持键盘操作，单选涂黑/撤销并有文本状态。

## 7. 验收

- 7 步字段、条件校验和材料要求符合 2025 模板；草稿重进完整恢复。
- 并发标签页保存触发版本冲突，不静默覆盖。
- 提交后所有写接口阻断；有权解锁且原因/操作者可追溯。
- 每个等级矩阵只有一个有效选中项。
- 生成 PDF 来源于不可变快照，内容完整且客户隔离正确。
- 本地快照、超时或 HTTP 受理响应都不能单独形成 `SUBMITTED`；只有同一 event 的权威回执身份、密文证据及摘要可证明提交成功。
