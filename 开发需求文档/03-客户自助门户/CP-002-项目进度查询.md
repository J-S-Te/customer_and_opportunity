# CP-002 项目进度查询

## 1. 目标与边界

客户查看自己的项目列表、详情、五阶段里程碑、动态、团队、延期预警并导出 PDF。Portal 只保存项目服务快照，不管理项目执行。

## 2. 同步

每 5 分钟按 customerId 增量拉取，或消费项目快照事件；以 `project_id + source_updated_at` upsert，旧事件不得覆盖新快照。同步失败保留最后成功数据，并展示“数据更新时间/可能延迟”。

## 3. 数据表

- `portal_project_snapshots(project_id,customer_id,project_name,contract_no,status,progress_pct,current_stage,expected_end_date,delayed,manager_name_snapshot,manager_contact_masked,manager_portal_account_id,source_updated_at,synced_at,raw_version)`；`manager_portal_account_id` 必须由项目服务提供权威 Portal 接收账号。缺失时联系能力失败关闭，严禁从姓名、`person_ref` 或脱敏联系方式推导。
- `portal_project_milestones(project_id,stage_code,stage_name,status,planned_at,completed_at,sort_no)`。
- `portal_project_activities(project_id,source_activity_id,type,content,occurred_at)`。
- `portal_project_team(project_id,person_ref,name_snapshot,role,contact_masked)`。

所有表索引必须以 customer_id 开头；project_id 全局不视为授权条件。

## 4. API

`GET /api/v1/projects`、`GET /api/v1/projects/{projectId}`、`GET /api/v1/projects/{projectId}/activities`、`POST /api/v1/projects/{projectId}/exports`。Service 从会话 customer_id 强制过滤，忽略客户端 customerId。

项目详情是有界载荷，只返回 `snapshot/milestones/team`；为兼容已发布客户端可保留 `activities: []`，但不得查询或内嵌动态历史。动态只由 `/activities` 返回，必须先按当前会话 tenant/customer 证明父项目可见，再使用 `page/page_size` 独立分页；默认 `1/20`，`page_size` 最大 100，按 `occurred_at DESC, id DESC` 稳定排序。页码非正整数、超过 page_size 上限、重复参数或未知 query 参数均返回 400，不静默归一化。

`project_id` 是项目服务生成的 opaque identifier，可能包含 `/` 等保留字符。客户端必须逐段 percent-encode，Portal Router 必须使用原始转义路径完成单段匹配后再解码参数；不得要求前端改写 ID，也不得把解码后的 ID 用于文件路径。所有读取仍以会话 tenant/customer 与完整 project_id 共同过滤。

PDF 导出异步生成，包含生成时间和数据更新时间；里程碑、团队等长内容必须换行分页，不得因单页布局截断。下载授权有效期 15 分钟，并绑定当前 tenant/customer/account/project。下载使用 at-most-once 语义：服务端必须在开始传输前以数据库行锁原子消费 token，同一 token 不可并发或重放；响应流中断时通过原导出任务申请新 token 重试，不重复创建导出任务。服务端“流写出成功”审计只代表本服务写入响应成功，不得解释为远端客户端已完整接收。

## 5. 前端

页面：我的项目、项目详情。详情包含概览卡、进度条、5 阶段时间线、动态、团队、延期提示。联系项目经理使用独立项目站内会话，不混用客户反馈；会话强绑定 tenant/customer/project/customer account/current manager account，只接受纯文本。客户与经理发送均要求持久幂等键，单会话单发送账号 5 分钟最多 10 条。客户和经理分别维护绑定权威账号的单调已读游标，推进目标必须是同会话中服务端真实投递给读取账号的消息，精确重放不重复审计，客户端不能声明 tenant/customer/manager 或未读数。经理变更后旧会话立即停止读写和推进回执，由新经理接收账号创建新会话，历史仅保留审计。

## 6. 验收

- 列表字段、里程碑和详情与项目服务快照一致，延迟正常 ≤5 分钟。
- 客户只能访问自己的项目；构造其他 projectId 返回 404/403 且不泄露是否存在。
- 下游失败时展示最后同步时间，不清空项目。
- PDF 与当前授权数据一致，链接过期或跨客户不能下载。
- PDF 长里程碑/团队数据跨页后无丢失；同一 token 并发仅一个请求可开始传输，响应写出失败记录失败审计且可为原任务申请新 token。
- P95 ≤2 秒，项目详情子区可并行/懒加载。

当前实现边界：详情、独立动态分页及前端并行加载已经实现。PDF 导出保留 opaque project_id 原值，捕获创建时的 tenant/customer/account/project 绑定不可变快照，以持久幂等任务异步生成；独立 Worker 支持过期租约接管、CJK 显示宽度换行和跨页，渲染失败明确落失败态；成功文件通过 15 分钟、只存 token 摘要且账号绑定的一次性授权下载，凭证不进 URL、请求体、日志或浏览器持久状态。站内项目会话已实现客户创建/读取/回复、项目系统经理机器读取/回复、纯文本、幂等、审计和事务内权威接收账号行锁复核；只有项目同步明确给出 `manager_portal_account_id` 才开放，接口受 `project.message.read/send` 和机器 scope `portal.project_message.manage` 控制。客户与经理已读 API、账号绑定单调游标和不可变推进审计已经实现，客户前端显示最新窗口后推进真实投递给本账号的最新经理消息；项目系统人工工作台仍需调用经理端接口完成 UI 联调。`MESSAGE_ACCEPTED` 仅表示本地持久化成功，`READ_RECEIPT_ADVANCED` 才表示对应账号确认读取到该消息边界。`000046/000050/000052` 已通过真实 MySQL 8.4 空库链验证，浏览器 E2E 仍待完成。
