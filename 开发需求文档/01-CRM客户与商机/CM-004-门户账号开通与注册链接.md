# CM-004 基础平台外部用户开通与 Portal 邀请

## 1. 目标与边界

CRM 用户从客户详情为登记联系人预置基础平台外部用户、分配 Portal 应用角色、建立 Portal 客户映射并生成一次性邀请链接。Portal 外部客户统一使用基础平台 OIDC，不提供自注册，也不维护客户密码。

责任边界：

- 基础平台：外部用户身份、登录凭据、密码设置/找回、锁定、MFA、Portal 角色分配和 OIDC Token；
- CRM：确认客户和联系人、发起预置、生成并管理 24 小时业务邀请；
- Portal：保存 `platform_user_id(OIDC sub) ↔ customer_id` 映射、执行 OIDC 登录和本地会话、落实客户数据隔离。

## 2. 前置条件

- 客户有效，存在唯一登记联系人且手机号/邮箱至少一个符合基础平台外部用户标识要求；
- 操作者有 `portal_account.provision` 且能访问该客户；
- CRM 使用独立机器 Client 调用基础平台外部用户/角色管理 API，scope 最小化，不复用浏览器、授权目录或审计 Client；
- Portal 的 Application、Environment、`portal_customer` 角色及 OIDC Client 已登记；
- Portal 将账号开通、禁用机器令牌的 `sub` 分别绑定到部署配置的 CRM OAuth Client subject，不以 scope 单独授权高影响账号动作；
- 同一客户联系人只维持一个有效平台用户映射，同一时刻最多一个 PENDING 邀请。

## 3. 开通与激活流程

1. CRM 校验客户、登记联系人、权限和当前映射。
2. CRM 调基础平台受控接口，按已确认的手机号/邮箱幂等查询或预置外部用户，获得稳定 `platform_user_id`（OIDC `sub`）。
3. CRM 为该用户分配 Portal 应用 `portal_customer` 角色；基础平台负责自身的凭据初始化或账号恢复流程，CRM 不接触凭据。
4. CRM 调 Portal `POST /internal/accounts/provision`，传 `customerId/platformUserId/displayName/contactSnapshot`，Portal 幂等建立 PENDING 映射。
5. CRM 生成 256-bit 随机 token，只保存 `SHA-256(token+pepper)`；同事务撤销旧 PENDING 邀请并写审计。
6. 用户打开 `<portal_public_url>/activate?token=...`；Portal 后端调用 CRM verify，得到 expected `platform_user_id/customer_id`，建立短效服务端激活上下文。
7. Portal 创建 OIDC state/nonce/PKCE，将激活上下文 ID 与 state 绑定后跳基础平台授权端点。
8. Portal 回调严格验证 Token；只有 `sub == expected_platform_user_id` 且具备 Portal 角色/权限时才激活本地映射。
9. Portal 调 CRM consume；CRM 在同一事务中按邀请完整身份绑定锁定对应链接，将 CRM 链接 `PENDING → ACTIVE`、邀请 `PENDING → USED` 并写审计。精确的 token/sub/链接重放在两项状态均已收敛时幂等成功；Portal 建立自己的服务端会话并进入业务页。

邀请链接不承载密码、OIDC Token 或平台管理凭据。若基础平台用户尚未完成自身凭据初始化，由基础平台登录页完成，不在 CRM/Portal 实现。

## 4. 状态机

邀请：`PENDING → USED | EXPIRED | REVOKED`。Portal 映射：`PENDING → ACTIVE → DISABLED`。平台用户状态是外部权威状态，Portal 通过 OIDC/UserInfo 校验，不复制为可独立登录的本地身份。

## 5. 数据模型

### `crm_portal_invites`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| invite_no | varchar(32) | 邀请业务号 |
| customer_id/contact_id | bigint | 客户和登记联系人 |
| platform_user_id | varchar(64) | 预期 OIDC sub |
| portal_account_id | varchar(64) | Portal 映射 ID |
| token_hash | char(64) | 唯一，禁止保存原 token |
| status | varchar(16) | PENDING/USED/EXPIRED/REVOKED |
| expires_at/used_at/revoked_at | datetime(3) | 状态时间 |
| revoked_reason | varchar(500) | 撤销原因 |

### `crm_portal_identity_links`

`customer_id,contact_id,platform_user_id,portal_account_id,status,provisioned_at,last_verified_at`，唯一 `(tenant_id,platform_user_id)` 和 `(tenant_id,customer_id,contact_id)`。

不建立密码、密码哈希、初始口令或 Portal JWT 密钥字段。

## 6. API

| 方法 | 路径 | 调用方 |
| --- | --- | --- |
| POST | `/customers/{id}/portal-invites` | CRM 前端，预置身份并生成/重发 |
| GET | `/customers/{id}/portal-invites/current` | CRM 前端，状态和脱敏身份摘要 |
| POST | `/portal-invites/{inviteNo}/revoke` | CRM 前端，需原因 |
| POST | `/internal/portal/invites/verify` | Portal 机器 Client |
| POST | `/internal/portal/invites/consume` | Portal 机器 Client |

verify 成功返回 `customerId,platformUserId,portalAccountId,expireAt`；失效统一为 `EXPIRED/USED/REVOKED/NOT_FOUND`。consume 必须同时提交 token、已认证 OIDC sub 和 Portal session request_id，CRM 校验 sub 匹配，并按 `tenant/customer/contact/platform_user/portal_account` 完整绑定激活 CRM 身份链接；错绑定或 `DISABLED` 链接失败关闭。

Portal 调用 verify/consume 使用独立基础平台 `client_credentials` Client（`client_secret_basic`），scope 固定为 `portal.invite.verify`。每次请求发送 RFC3339Nano UTC `X-Integration-Timestamp` 和一次性 256-bit 随机 `X-Integration-Nonce`。当前基础平台 token 端点不接受非标准 audience 表单参数，并对 application Token 使用部署级统一 audience；CRM 必须按平台实际 `AUTH_APPLICATION_JWT_AUDIENCE` 严格验证。接口响应统一使用 `code/message/request_id/data` 信封。

基础平台/Portal 适配器接口名以联调提供的正式 OpenAPI 为准，开发规格只固定语义：`ProvisionExternalUser`、`AssignApplicationRole`、`ProvisionPortalMapping`。

## 7. 一致性与补偿

- 平台用户已创建但角色分配失败：不生成邀请，记录补偿任务重试角色分配；
- 平台角色已分配但 Portal 映射失败：不生成邀请，重试映射；达到上限进入人工对账；
- 邀请写入失败：已预置身份和映射保留为 PENDING，可幂等重试生成邀请；
- 重发邀请不重复创建平台用户/角色/Portal 映射，只撤销旧 token；
- 联系人变更或 CRM 撤销访问时，撤销 PENDING 邀请，并触发 Portal 映射禁用和基础平台 Portal 角色回收；Portal 映射状态、该 subject 全部本地会话、机器业务幂等账本和最小化认证审计必须同事务提交，审计失败整体回滚；任一步失败进入补偿/对账；
- verify 不消费；只有 OIDC 回调 sub 匹配并成功建立映射后 consume。

## 8. 前端

客户详情“门户访问”卡展示平台用户状态、Portal 映射状态、脱敏联系人、邀请状态和过期时间。提供预置并生成、复制一次、重发、撤销。当前邀请默认 24 小时有效；文案明确“点击链接后通过统一身份平台登录”，不展示账号密码或默认口令。

## 9. 验收标准

- 缺有效登记联系人时阻断；越权用户前后端均无权开通。
- 重复请求复用同一 platform_user_id 和 Portal 映射，不产生重复角色绑定。
- token 24 小时、一次性；原 token、密码、OIDC Token 和平台 Secret 不落日志/数据库。
- OIDC 回调 sub 与邀请预期不一致时拒绝、邀请保持 PENDING 并审计。
- consume 前失败可重新登录；consume 后 token 不可复用。
- 撤销访问最终同时收敛邀请、Portal 映射和基础平台 Portal 角色，失败可观测并可重试。
