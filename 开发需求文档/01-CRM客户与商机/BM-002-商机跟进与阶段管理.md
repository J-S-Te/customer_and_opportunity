# BM-002 商机跟进与阶段管理

## 1. 最新业务决策

商机阶段为：`初步接触、需求沟通、方案制定、报价、投标、已签约、失败`。所有人工阶段推进、回退、跳转、进入终态和终态重开均不审批，有权用户提交后立即生效并审计。

人工进入已签约必须关联合同；人工进入失败必须填写标准失败原因。可信投标回传例外：中标缺合同仍直接进入已签约并标记待关联合同；落标缺原因仍直接进入失败并标记待补原因。

## 2. 状态与不变量

- 前 5 阶段：`opp_status=FOLLOWING`；终态：`opp_status=CLOSED`。
- `已签约` 与 `失败` 互斥。
- 人工已签约：合同 customerId 必须等于商机 customerId。
- 人工失败：`lost_reason` 必须是 `价格/技术/关系/客户预算/竞争对手/其他`；其他需补充说明。
- 外部中标缺合同：`contract_ref=NULL,terminal_pending_type=CONTRACT`。
- 外部落标缺原因：`lost_reason=NULL,terminal_pending_type=LOST_REASON`。
- 补齐待办不改变阶段；重开到推进阶段时清除关闭状态和不适用的终态字段，但日志保留原值。
- 人工调整优先于较早的外部事件；外部事件按 `changed_at` 和已消费版本防止旧事件覆盖新人工状态。

## 3. 阶段变更事务

Service 在单事务中：锁定商机 → 校验 version、权限与规则 → 更新阶段/终态字段 → 写 `crm_opportunity_stage_logs` → 创建提醒/outbox → 提交。阶段日志字段：`from_stage,to_stage,source=MANUAL|QB_CALLBACK,source_id,reason,contract_ref,lost_reason,pending_type,operator_id,changed_at,request_id`。

## 4. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/opportunities/board` | 7 列看板，受数据范围控制 |
| POST | `/opportunities/{id}/stage-changes` | 任意人工调整，无审批 |
| GET | `/opportunities/{id}/stage-history` | 变更历史 |
| POST | `/opportunities/{id}/followups` | 跟进记录 |
| GET | `/opportunities/{id}/followups` | 跟进时间线 |
| PUT | `/opportunities/{id}/terminal-todo` | 补合同/失败原因 |
| POST | `/internal/integrations/qb/status-events` | 报价/投标可信回传 |
| GET | `/opportunities/{id}/external-status` | 外部状态快照 |

人工阶段变更请求：

```json
{
  "target_stage": "已签约",
  "reason": "客户已签署合同",
  "contract_ref": "HT202607200001",
  "lost_reason": null,
  "version": 7
}
```

外部回传以 `sourceId-status` 幂等；机器 Token 必须限制到 CRM audience 和 `opportunity.status.write` scope。

## 5. 外部状态映射

| 回传 | 处置 |
| --- | --- |
| 报价审批中 | 维持报价，更新只读状态 |
| 报价已通过 | 维持报价，允许人工后续调整 |
| 报价已失效 | 自动回方案制定，记录外部来源 |
| 投标标书制作/开标中 | 维持投标 |
| 投标中标 | 直接已签约；有合同则关联，无则待关联合同 |
| 投标落标 | 直接失败；有原因则写入，无则待补原因 |

事件重复不重复写日志；乱序事件小于 `external_status_changed_at` 时忽略并审计为 STALE。

## 6. 超时预警

仅前 5 阶段计时。阈值按阶段配置；Job 每 10 分钟扫描，使用 `(opportunity_id,stage,threshold_version)` 幂等创建站内消息。终态、作废和已提醒未跨新阈值的不重复通知。

## 7. 前端

- 7 列看板和商机详情均提供“调整阶段”；终态也可操作重开。
- 调整弹窗允许选择任意目标阶段，动态展示合同选择或失败原因字段；按钮文案“确认变更”，不出现审批提示。
- 外部中标/落标后立即进入终态；缺失字段显示黄色待办，不显示为仍在投标。
- 待办卡提供“关联合同”或“补充原因”；看板卡同时显示外部状态和终态待办。
- 跟进内容支持安全富文本，不允许未清洗 HTML。

## 8. 权限与审计

`opportunity.stage.change` 控制阶段操作，数据范围仍限制本人/组织/全部。外部机器身份不继承人工权限，只能提交约定事件。阶段日志不可修改或删除。

## 9. 验收标准

- 任意人工阶段调整无需审批且提交后立即可见；无任何“待审批”中间状态。
- 人工已签约缺合同、人工失败缺原因均被阻断。
- 外部中标缺合同直接已签约 + 待关联合同；外部落标缺原因直接失败 + 待补原因。
- 终态可直接重开，无审批；原终态信息和原因可审计。
- 重复/乱序回传不会重复流转或覆盖更新状态。
- 看板 7 列、列表、详情和统计的阶段口径一致。
- 越权阶段变更返回 403；并发版本冲突返回 409，不静默覆盖。
