# CM-001 客户信息录入与维护

## 1. 目标与范围

建立 CRM 客户主档，支持新建、编辑、查重、导入、合并、作废、敏感字段控制和完整审计。CM-003 信用评级已删除，本需求不得出现信用等级、评分或风险标记。

角色：销售维护本人客户；销售总监/客户管理员维护授权范围客户；财务或专门权限角色查看财务敏感字段；审计员只读日志。

## 2. 业务规则

1. 客户号格式 `KH + YYYYMMDD + 4 位流水`，由服务端事务内生成，全租户唯一。
2. 必填：客户名称、客户类型、行业、区域、登记联系人姓名、登记联系人电话、负责人。
3. 统一社会信用代码存在时按租户精确唯一；名称保存前执行规范化后的模糊查重。
4. 精确信用代码重复直接阻断；名称疑似重复返回候选列表，由具备 `customer.duplicate.override` 的用户填原因后允许继续。
5. 电话、税号、银行账号等敏感字段加密落库；普通读权限只返回脱敏值。
6. 合并以目标客户为存续主档：商机、沟通、联系人和邀请关系迁移；源客户标为已合并，不物理删除；整个操作单事务并记录映射历史。
7. 作废使用状态和 `end_date`，存在进行中商机、有效邀请或未完成售前任务时默认阻断，并返回阻断项。
8. Excel 导入采用“上传→预校验→确认导入”；允许部分成功，错误报告精确到行、列和错误码。
9. 所有修改要求填写变更原因；字段级 before/after 写 append-only 审计。
10. 交互式创建必须携带 `Idempotency-Key`。同一租户、操作人、键和规范化完整载荷精确重放首次脱敏响应；同键异载荷返回 409，不能重复生成客户号、客户、联系人或审计。导入行继续使用导入作业自身的行级幂等协议，不复用该键。

## 3. 状态

`ACTIVE（有效） → VOID（作废）`；`ACTIVE → MERGED（已合并）`。作废恢复需 `customer.restore` 权限并审计，本期不提供源客户反合并。

## 4. 数据模型

### `crm_customers`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| customer_no | varchar(32) | 非空，唯一 `(tenant_id, customer_no)` |
| name / normalized_name | varchar(200) | 非空；规范名建普通索引 |
| unified_credit_code_cipher | varbinary(512) | 可空，加密值 |
| unified_credit_code_hmac | char(64) | 可空，唯一 `(tenant_id, hmac, deleted_at)` |
| customer_type / industry / region | varchar(64) | 非空，使用业务字典 |
| owner_user_id / owner_org_id | varchar(64) | 数据范围依据 |
| status | varchar(32) | ACTIVE/VOID/MERGED |
| end_date | date | 作废/合并时填写 |
| merged_into_id | bigint | MERGED 时指向存续客户 |
| finance_json | json | 低频财务扩展；敏感值仍加密 |

### 子表

- `crm_customer_contacts`：联系人、类型、是否登记联系人、加密电话/邮箱、排序；同一客户只能有一个有效登记联系人。
- `crm_customer_stakeholders`：干系人角色、影响力、关系描述。
- `crm_customer_systems`：信息系统名称、等级、场景等；不含信用评级。
- `crm_customer_merge_logs`：源/目标、迁移数量、原因、操作者。
- `crm_customer_change_logs`：字段级变更审计，只插入。
- `crm_customer_create_idempotency`：操作人绑定创建键、规范化请求摘要、客户引用及首次脱敏响应快照；不保存电话、邮箱、统一社会信用代码明文。
- `crm_import_jobs`、`crm_import_rows`：上传批次、校验/导入结果和错误。

## 5. 后端模块

`internal/modules/customer` 提供 `CustomerService`：

```go
Create(ctx, CreateCustomerCommand) (*Customer, error)
Update(ctx, id, expectedVersion, UpdateCustomerCommand) (*Customer, error)
CheckDuplicate(ctx, DuplicateQuery) ([]DuplicateCandidate, error)
Merge(ctx, MergeCustomerCommand) error
Void(ctx, id, reason, expectedVersion) error
PreviewImport(ctx, file) (*ImportJob, error)
CommitImport(ctx, jobID) (*ImportResult, error)
```

创建/更新在事务中完成主表、子表、审计和 outbox。编号生成使用 `biz_sequences(tenant_id,biz_date,biz_type,current_value)` 行锁，不使用查询最大值。

## 6. API

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/customers/duplicate-check` | customer.create/update | 保存前查重 |
| POST | `/customers` | customer.create | 创建客户；必须传 `Idempotency-Key` |
| PUT | `/customers/{id}` | customer.update | 更新，必须传 `version/reason` |
| POST | `/customers/{id}/void` | customer.void | 作废 |
| POST | `/customers/{id}/restore` | customer.restore | 恢复作废客户 |
| POST | `/customers/merge` | customer.merge | 合并两个客户 |
| POST | `/customers/imports/preview` | customer.import | 上传并校验 |
| POST | `/customers/imports/{jobId}/commit` | customer.import | 确认导入 |
| GET | `/customers/imports/{jobId}/errors` | customer.import | 下载错误报告 |

创建示例字段：`name/customer_type/industry/region/owner_user_id/contacts/stakeholders/systems/finance/reason`。响应不返回未授权敏感明文。

## 7. 前端

页面：客户新建/编辑页、查重候选弹窗、导入向导、合并向导、作废确认弹窗。核心组件：`CustomerBaseForm`、`ContactEditor`、`StakeholderTable`、`DuplicateCandidates`、`ImportResultTable`、`SensitiveField`。

交互要求：

- 保存前失焦或提交触发查重；候选项可打开只读详情。
- 联系人编辑保证且仅保证一个登记联系人。
- 导入先展示总行数、可导入、警告、错误；确认后显示逐行结果。
- 合并页左右对比字段，明确目标客户和将迁移的关联数量。
- 无敏感权限时前端不提供“查看明文”按钮。
- 同一规范化创建载荷在当前页面生命周期复用同一显式幂等键，只有服务端确认成功后才清除；禁止把含敏感字段的载荷或摘要写入 localStorage、sessionStorage 或 URL。整页重载后的模糊结果须先查询服务端状态。

## 8. 异常与安全

- 重复代码/名称、版本冲突、依赖阻断分别返回 409/422 及结构化 details。
- Excel 限制格式、大小、行数；文件先病毒扫描，公式单元格按文本处理，防 CSV 注入。
- 合并接口加资源级锁，防止同一客户并发参与两次合并。
- 查询日志、埋点和错误响应不得包含敏感字段明文。

## 9. 验收标准

- 编号并发生成不重复；信用代码精确重复无法保存。
- 名称疑似重复有候选和授权覆盖流程。
- 普通销售 API 响应和页面均为脱敏值，数据库为密文。
- 合并后全部关联转到目标客户，源客户可追溯且不可再编辑。
- 作废不产生物理 DELETE，阻断项准确。
- 导入错误定位到行列，成功行不因失败行回滚。
- 审计记录含操作者、原因、request_id、before/after，且不可修改。
- 创建超时后的同键重试返回首次脱敏响应且不重复写入；跨操作人或同键异载荷不得命中原结果。
