# CM-002 客户查询与检索

## 1. 目标

提供客户列表、卡片、快捷筛选、详情分 Tab 和受控导出；所有查询受租户、角色和负责人数据范围约束。

## 2. 查询能力

筛选项：客户号/名称关键词、客户类型、行业、区域、负责人、创建时间、最近跟进时间、状态。快捷筛选：重点客户、新增客户、成交客户、待跟进；“高价值客户”旧信用口径不得保留。

排序白名单：创建时间、更新时间、客户名称、最近跟进时间、商机金额汇总。默认 `updated_at DESC,id DESC`。

详情 Tab：基本信息、联系人/干系人、商机历史、项目历史快照、沟通记录、操作日志。首屏只加载摘要，其余 Tab 按需加载。

## 3. 数据与索引

- `crm_customers`：`(tenant_id,status,owner_user_id,updated_at)`、`(tenant_id,industry,region)`。
- 名称检索先采用 normalized_name 前缀/包含策略；数据量超过阈值后接 MySQL FULLTEXT 或独立搜索服务，业务接口不变。
- `crm_customer_followups`：客户、类型、内容（清洗后富文本）、跟进时间、跟进人、下次跟进时间。
- 项目历史只读来自 Portal/项目服务拥有的快照或受控接口，不复制项目执行主数据。

## 4. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/customers` | 分页查询，返回脱敏摘要 |
| GET | `/customers/{id}` | 基本详情 |
| GET | `/customers/{id}/contacts` | 联系人与干系人 |
| GET | `/customers/{id}/opportunities` | 商机历史 |
| GET | `/customers/{id}/projects` | 项目快照 |
| GET | `/customers/{id}/followups` | 沟通记录分页 |
| POST | `/customers/{id}/followups` | 新增沟通记录 |
| GET | `/customers/{id}/audit-logs` | 操作日志，需 audit 权限 |
| POST | `/customer-exports` | 创建异步导出任务 |
| GET | `/customer-exports/{jobId}` | 查询状态/获取短效下载链接 |

列表 query：`keyword,type,industry,region,owner_id,status,quick_filter,created_from,created_to,page,page_size,sort_by,sort_order`。服务端忽略或拒绝试图扩大数据范围的 tenant/owner 参数。

## 5. 后端实现

`CustomerQueryService` 将权限 Claims 转换为 `DataScope`，Repository 所有查询从 scope 构造器开始。详情先验证资源可见性，再查子资源，禁止“先按 id 查出再判断”。

导出为异步 Job：固定查询快照和字段清单，生成 xlsx，文件加密存储，下载链接 15 分钟有效；导出数量上限和频率可配置。敏感字段是否导出由 `customer.sensitive.export` 单独判断。

## 6. 前端

页面：客户列表/卡片双视图、客户详情。组件：`CustomerFilters`、`QuickFilterBar`、`CustomerTable`、`CustomerCards`、`CustomerTabs`、`FollowupTimeline`、`ExportDrawer`。

- 筛选条件写入 URL；切换视图保留条件和分页。
- 详情 Tab 首次点击请求并缓存，客户版本变化后失效。
- 导出必须展示字段选择、结果数量、敏感字段提示和任务进度。
- 加载、空态、无权限、依赖项目服务失败分别展示。

## 7. 性能与验收

- 100 并发下常用列表 P95 ≤ 2 秒；分页结果无重复/遗漏。
- 销售只能查询本人客户，即使构造客户 ID、owner_id 或导出请求也不能越权。
- 列表、详情和导出脱敏策略一致。
- 组合筛选、排序、列表/卡片切换结果一致。
- 项目 Tab 依赖失败不影响客户基本详情，显示“暂时无法获取项目数据”。
- 富文本跟进内容入库前清洗，展示不产生 XSS。
