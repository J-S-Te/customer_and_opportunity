# TS-011 售前两级执行指派（团队负责人）

> 状态：需求已确认；2026-10-22静态核对已有后端、前端、通知与超时实现，不代表目标环境部署验收。当前实现与边界见[模块上下文](../../../.ai/modules/presale-two-level-assignment.md)。
> 前置：扩展 [TS-003 人员指派](TS-003-人员指派.md)、[TS-002 两级审批](TS-002-两级审批.md)
> 提出日期：2026-10-18

## 1. 背景

TS-003 定义的是**一级指派**：审批通过后，规则中配置的执行角色一次性选定执行人，申请直接进入 `EXECUTING`。

实际业务需要**两级**：技术总监先定「哪个部门、谁是这个部门的负责人」，再由**团队负责人**决定「具体谁来执行」。

## 2. 目标流程

```
审批通过
  ↓
APPROVED_PENDING_ASSIGNMENT
  ↓ ① 技术总监：选择执行部门 + 选择团队负责人
PENDING_EXECUTION_ASSIGNMENT
  ↓ ② 团队负责人：选择执行人（项目经理 / 本人 / 其他授权人员）
EXECUTING
  ↓ ③ 执行人单独结束；或替换指派后全部当前执行人已有有效工时
COMPLETED
```

与 TS-003 的差异：**新增第 ① 级**，并把第 ② 级的指派权从「规则配置角色」改为「被指派的团队负责人」。

## 3. 已确认结论（2026-10-18）

| # | 问题 | **结论** | 影响 |
| --- | --- | --- | --- |
| Q1 | 团队负责人是「技术总监从人员目录挑选」，还是「选部门后系统自动带出该团队负责人」？ | **挑选**（人员目录已有部门与角色字段，可先按部门过滤再选） | 决定是否需要「部门↔负责人」映射表 |

| Q3 | ① 完成后、② 完成前，申请状态叫什么？ | 新增 `PENDING_EXECUTION_ASSIGNMENT` | 影响状态机、列表筛选、通知 |
| Q4 | 团队负责人**拒绝**或**超时**如何处理？ | 拒绝 → 退回 `APPROVED_PENDING_ASSIGNMENT` 由技术总监重选；超时先只做提醒（复用 TS-008 预警） | 影响状态机与预警 |

## 4. 规则模型变更

现有规则节点（`ApprovalNode`）已能表达「角色 + 动作」：

| 节点类型 | 含义 | 新语义 |
| --- | --- | --- |
| `APPROVAL` | 审批 | 不变 |
| `DEPARTMENT_ASSIGNMENT` | 选部门 | 由**技术总监**执行（第 ① 级） |
| `PERSON_ASSIGNMENT` | 选人 | 拆成两种：`TEAM_LEAD_ASSIGNMENT`（第 ① 级，选团队负责人）/ `EXECUTOR_ASSIGNMENT`（第 ② 级，选执行人） |

**必须解除的现有约束**：`approval_rule_store.go` 禁止同一角色配置两个执行动作；技术总监需要同时承担「选部门」和「选团队负责人」。

## 5. 影响面

| 层 | 变更 |
| --- | --- |
| 数据 | 申请记录新增：团队负责人 `person_id`、当前指派级别；`crm_presale_assignments` 增加角色语义（团队负责人 / 执行人） |
| 状态机 | 新增一个中间态；两级完成的判定；拒绝与失效回退 |
| 权限 | 第 ② 级的指派权限判定从「规则角色」改为「当前团队负责人本人」 |
| 接口 | 拆分/新增：`PUT …/execution-department`（含负责人）、`PUT …/executor-assignments`（团队负责人执行）；**旧接口保留**以兼容 |
| 快照 | 规则快照仍固化节点，历史申请不受新规则影响 |
| 通知 | 团队负责人被指派后收到待办；拒绝/失效通知技术总监 |
| 前端 | 技术总监与团队负责人看到**不同**的操作入口，按当前指派级别渲染 |
| 迁移 | 需要000114/000115新增列、索引、CHECK及通知形状；历史EXECUTING/COMPLETED不回填，并非无需schema迁移。新通知身份另需000121 |

## 6. 验收标准（草案）

- 技术总监提交「部门 + 团队负责人」后，申请进入中间态，且**只有**该团队负责人能看到执行指派入口；
- 团队负责人选择项目经理/本人/他人后，申请进入 `EXECUTING`，执行人收到通知；
- 技术总监未选团队负责人时，任何人不能推进到 `EXECUTING`；
- 团队负责人被停用后，在途申请进入待重选，且不能继续推进；
- 历史 `EXECUTING` / `COMPLETED` 申请的状态与指派记录**完全不变**；
- 规则保存允许技术总监同时承担两个动作，但仍禁止同类型动作重复配置；
- 全链路有测试覆盖：状态机、权限边界、快照不回改历史。
