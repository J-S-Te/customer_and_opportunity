# TS-007 售前列表与角色视图

## 1. 数据范围

| 角色 | 范围 |
| --- | --- |
| 销售 | 自己发起的任务 |
| 售前执行主体 | 当前或历史被指派给权威 `person_id` 的任务 |
| 销售总监 | 全部 |
| 团队负责人 | 全部 |
| 技术负责人/管理层 | 全部只读或按权限操作 |

多角色取权限并集但不突破 `max_effective_roles` 和服务端范围策略。前端视图标签只是快捷条件，不能扩大后端范围。

## 2. 查询

筛选：任务号、商机、申请人、执行人、状态、场地类型、紧急度、申请/期望时间、是否超时、推送状态。支持列表和按状态看板；两种视图使用同一 Query Service。

索引：request 表 `(tenant_id,status,created_at)`、`(tenant_id,applicant_id,status)`；assignment `(tenant_id,assignee_id,is_current,request_id)`。

## 3. API

`GET /presale/requests`、`GET /presale/board`、`GET /presale/filter-options`。服务端从 Claims 计算 scope，不接受 `scope=all` 作为授权依据。

列表摘要：任务号、商机、申请人、当前执行人、状态、紧急度、期望结束、超时标记、累计小时、PMS 推送异常数、available_actions。

## 4. 前端

`PresaleList.vue`、`PresaleBoard.vue`、`PresaleFilters.vue`。销售默认“我的申请”，有权威 `person_id` 的执行主体默认“我执行的”，管理角色默认“全部”。PMS 指派角色属于业务角色，不能猜测等同 CRM OIDC 角色；数据范围以认证权限、非空权威 `person_id` 和真实当前/历史指派关系共同确定。URL 保存筛选；看板拖拽不改变状态，因为 TS 状态由审批/指派/工时触发。

## 5. 验收

- 五类角色可见范围与矩阵一致，构造 task ID 不能越权。
- 团队负责人和销售总监可见全部；有权威 `person_id` 的主体能查看历史参与任务但不能操作非当前任务；映射缺失时不得回退 OIDC `sub/user_id`。
- 筛选、分页、列表/看板数量一致；P95 ≤ 2 秒。
- 页面无角色硬编码演示数据；权限变化重新登录/刷新后生效。
