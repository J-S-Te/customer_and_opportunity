# TS-004 过程记录与状态机

## 1. 状态机

```text
APPROVAL_STARTING → PENDING_APPROVAL → APPROVED_PENDING_ASSIGNMENT
                                           ↓ 两级规则先进入 PENDING_EXECUTION_ASSIGNMENT，再选择执行人；旧规则直接指派
                                        EXECUTING
                                           ↓ 人工完成；或保存指派替换后全部当前执行人已有有效工时
                                        COMPLETED

PENDING_APPROVAL → REJECTED
PENDING_APPROVAL / APPROVED_PENDING_ASSIGNMENT / EXECUTING → CANCELLED
```

2026-10-22：REJECTED/CANCELLED可由有权发起人经reopen在原任务上重新发起审批，保留历史并重置审批轮次；COMPLETED不开放该重开。取消还覆盖PENDING_EXECUTION_ASSIGNMENT；负责人拒绝/失效按TS-011回退，不新建申请冒充原流程。

## 2. 进度记录

仅当前执行人可在 EXECUTING 状态新增进度；内容为 1～2000 字文字和受控 `https` 链接，不支持附件、方案文档或技术标。记录创建后不可编辑/删除，纠错通过新增说明。

进度、收件证据与outbox原子提交。可信收件人为申请人和发生时其他当前执行人；申请人为USER，执行人按指派显式namespace写USER或历史PERSON，作者只在对应命名空间排除。000121不猜测回填历史。Worker只消费证据ID，按tenant重读任务、进度、发生时指派和稳定ID，以fencing token/租约/有限重试幂等投影；不承诺IM/邮件/短信。

取消规则：申请人在待审批可取消；团队负责人/管理者在待指派或执行中可取消；必须填写原因。完成后不可取消。

取消请求必须携带 `Idempotency-Key`。Service 在事务中锁定父任务，先验证申请人/团队负责人/显式取消权限，再按 `actor + request_id + CANCEL + 规范化原因 + version` 判断重放。精确重试保持成功且不重复状态日志；同键不同执行人、任务或原因返回 409。

## 3. 数据

- `crm_presale_progress_logs(request_id,author_id,content,link_url,progress_pct,created_at)`；进度百分比可空、0～100，仅展示不驱动完成。
- `crm_presale_status_logs(request_id,from_status,to_status,trigger,reason,operator_id,occurred_at,request_id_trace)`，只插入。

## 4. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/presale/requests/{id}/progress` | 新增进度 |
| GET | `/presale/requests/{id}/timeline` | 聚合状态、审批、指派、进度、工时时间线 |
| POST | `/presale/requests/{id}/cancel` | 取消任务 |
| GET | `/presale/requests/{id}/available-actions` | 后端计算可用动作 |

时间线采用稳定 cursor 分页，事件按 occurred_at + id 排序。

## 5. 前端

任务详情以时间线展示全流程；操作区严格使用服务端 `available_actions`。进度编辑器只允许文本和链接；状态显示中英文映射，不直接暴露内部枚举。

## 6. 验收

- 全部合法迁移成功，非法跳转返回 409 并保持原状态。
- 非当前执行人不能写进度；HTML/脚本被拒绝或清洗。
- 取消角色、阶段和原因校验正确；终态无取消入口且 API 也阻断。
- 时间线完整、稳定排序、不可篡改。
- 进度、收件人证据和 outbox 同事务；精确幂等重放不重复通知，申请人和执行人收件箱命名空间不可混用。
- 进度100%和单独登记工时均不自动完成；人工完成与指派替换自动完成分别按TS-005验收。
