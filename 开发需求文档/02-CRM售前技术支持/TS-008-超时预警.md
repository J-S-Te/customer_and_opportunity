# TS-008 售前超时预警

## 1. 预警规则

配置项：节点 1 审批时限、节点 2 审批时限、审批后待指派时限、执行截止提前提醒、执行超期。配置以小时为单位，支持租户级覆盖并记录版本。

对象与接收人：

- 节点 1 审批超时：本地 CRM OIDC 有效会话目录中的销售总监，使用 `USER/user_id`；审批引擎未提供权威当前审批人时不得猜测或声称已通知当前审批人；
- 节点 2 审批超时、指派超时：本地 CRM OIDC 有效会话目录中的团队负责人，使用 `USER/user_id`；
- 执行即将/已经超期：当前执行人使用 `PERSON/person_id`，申请销售和上述团队负责人使用 `USER/user_id`；
- `sales_director`、`team_lead` 是基础平台签名的 CRM 角色，不是 PMS 人员池角色；角色收件人只能从同租户、未撤销、未过期且角色精确匹配的本地 OIDC 会话投影，不能查询 PMS 工程师表猜测；
- 已完成/驳回/取消不再触发。

## 2. 数据

- `crm_presale_alert_rules(type,threshold_hours,enabled,config_version)`；
- `crm_presale_alerts(request_id,alert_type,rule_version,due_at,status,recipient_kind,recipient_id,sent_at,read_at)`；`recipient_id` 为大小写敏感的 128 字符，覆盖基础平台 OIDC subject 上限，PERSON 值仍必须满足 PMS 64 字符契约；
- `recipient_kind` 新数据只允许 `USER` 或 `PERSON`，唯一 `(tenant_id,request_id,alert_type,rule_version,recipient_kind,recipient_id)` 防重复；相同原始 ID 在两个命名空间中是两个不同收件人；
- `000071` 对无法证明来源的存量 `recipient_id` 不做映射，保留为个人 API 无法命中的 `LEGACY_UNKNOWN`。旧 PENDING 预警及未发送 outbox 取消；旧 UNREAD/READ 仅保留为历史证据，不投影给任何账号。

## 3. 后端

Scheduler 每 10 分钟扫描，按状态进入时间/expected_end 算 due_at；创建站内消息 outbox。outbox 投影前再次校验租户、PENDING 状态及 `USER/PERSON` 命名空间，缺失、取消或 legacy 数据安全取消而不投递。任务状态改变后将未发送或未读的旧预警取消。配置更新不回溯已发送消息，只影响新扫描。

API：规则管理（`presale.alert.config`）、预警列表、已读；任务列表只返回聚合超时标志。个人列表和已读谓词固定为 `(USER, actor.UserID)` 与仅在非空时加入的 `(PERSON, actor.PersonID)` 的精确并集；`ScopeMode=SELF/ORG/ALL` 均不能扩大，禁止从 `sub`、账号、员工号或相同字符串推断 `person_id`。

## 4. 前端

管理配置页显示阈值、启停、更新时间；任务列表/详情显示“即将超时/已超时”及起算点。个人预警区明确其 user/person 精确并集边界；通知点击跳任务详情，无权限时显示资源不可访问。

## 5. 验收

- 各状态按正确时间点触发且不重复；状态完成后不再提醒。
- 只发送站内消息，本期不调用 IM/短信/邮件。
- 多实例调度不重复发信；时区和夏令时不影响计算。
- 同一字符串同时作为 `user_id` 和 `person_id` 时，两类预警均可独立创建、读取和已读；person 绑定为空时不能读取 PERSON 预警，ALL 数据范围也不能越权读取他人预警。
- 销售总监只从本地 CRM OIDC 角色目录解析，PMS 人员池角色不得产生销售总监收件人；外部实际当前审批人不可解析时保持失败关闭。
- 存量收件人不猜测命名空间，旧 PENDING 不会被投递给碰巧同 ID 的用户或人员。
- 预警触达可统计，目标 ≥95%。
