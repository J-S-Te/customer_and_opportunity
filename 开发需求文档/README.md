# 客户与商机业务域开发需求文档

> 版本：V1.0  
> 日期：2026-07-31  
> 后端：Go + Gin + GORM + MySQL 8，模块化单体  
> 前端：Vue 3 + Vite + Vue Router，沿用统一前端 JavaScript/原生 fetch 工程  
> 依据：根目录 README、ISSUES、两个 HTML 原型及《新子系统开发对接交付清单》

> 当前实现同步（2026-08-27）：Portal 邀请链接有效期为 24 小时；登录使用基础平台 OIDC Code + PKCE。具体实现以 CM-004、CP-001 和 `DEVELOPMENT.md` 为准。

1. 先读 [总体架构](00-公共设计/00-总体架构.md)、[API 与后端规范](00-公共设计/01-后端与API规范.md)、[前端规范](00-公共设计/02-前端工程规范.md)。
2. 按需求编号阅读 01～03 目录中的开发规格。
3. 联调前阅读 [跨系统集成](04-集成与验收/01-跨系统集成.md) 和 [完成定义](04-集成与验收/02-开发验收与完成定义.md)。

## 2. 权威性

出现冲突时按以下优先级执行：

1. 用户已确认的最新业务决策；
2. 本目录开发规格；
3. 根目录 README；
4. ISSUES 中 PRD、测试策略、测试用例和 T5 契约；
5. HTML 原型只作为页面布局和交互参考。

已覆盖旧文档的决策：

- 删除 CM-003 信用评级及全部相关字段、权限、接口和展示；
- 商机所有阶段调整均无需审批，立即生效并审计；
- 投标中标缺合同仍直接进入“已签约”，标记“待关联合同”；
- 投标落标缺原因仍直接进入“失败”，标记“待补原因”；
- TS 单人指派首笔有效工时自动完成；多人指派须所有当前执行人均至少提交一笔有效工时后自动完成；
- 工时标准单位为小时，默认 `1 人天 = 8 小时`；
- CRM 与 Portal 是两个独立子系统，TS 是 CRM 内嵌模块。
- Portal 外部客户采用基础平台 OIDC；固定初始口令、Portal 本地密码和独立 portal-jwt 方案已废止。
- 客户自助门户不涉及与公安相关的对接：CUS-004 备案范围止于表单填写、实时校验、暂存、备案材料/PDF 生成与本地锁定，Portal 不实现公安提交、回执或公安 Provider 对接。
