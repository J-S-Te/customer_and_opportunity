# CRM 审计重试与 binlog 优化

## 暂停语义

来源不匹配的审计事件保留 `delivery_status=RETRY`、原始事件 ID、来源环境和 attempts，设置 `next_attempt_at=NULL` 并清除领取租约。该状态不自动重试、不算投递成功，也不删除证据。现有领取条件 `next_attempt_at<=now` 排除 NULL；恢复流程仅恢复 STARTED 和超时 PROCESSING，不会激活暂停事件。无需 schema 迁移，也兼容旧投递器。

新代码在领取后按 application/environment 拆分，错误来源暂停，正常记录独立投递。状态接口新增 `held_count`，仅统计 RETRY + NULL next_attempt_at + SOURCE_MISMATCH，属于 `retry_count` 的子集。`oldest_undelivered_at` 仍包含暂停记录，不能把暂停等同于积压已清空。

暂停或重试状态持久化失败会返回错误；投递循环通过现有 slog 输出脱敏错误分类，每个 worker 最多每分钟一条失败日志，避免故障期间刷屏。日志不输出事件内容、凭据或原始数据库错误。

该改动仅处理确定的事件来源不匹配；401/403、通道熔断、健康检查降采样和 binlog 参数不属于本次变更。

## 恢复与重放

先确认事件真实来源和正确的目标投递器；不得为消除失败将 dev 批量改成 prod。备份用于核对原始内容，禁止将整表备份覆盖到正在写入的生产表。确需回滚本次暂停时，按备份与操作批次筛选仍保持相同暂停状态的事件，仅恢复调度字段，保留后续业务数据。重放保留 event_id，并验证平台去重结果。逐批检查数量、状态、失败原因和新增 binlog；未经来源修正直接恢复调度会重新产生原故障。
