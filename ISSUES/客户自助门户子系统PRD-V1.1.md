## 0. 拆分与范围变更说明

### 0.1 拆分决策

将《需求说明书 V1.2》中 **CP-001 客户门户访问控制、CP-002 项目进度查询、CP-003 电子报告申请与发放、CUS-004 备案信息填写、CP-004 客户反馈与服务评价** 从客户与商机管理子系统剥离，独立组建 **「客户自助门户子系统 V1.0」**。

决策依据：
- 门户的服务对象是**外部客户**（业主/三方/政府/事业单位），与企业内部销售、客户成功团队的经营系统，在用户身份、安全合规要求（HTTPS、审计、权限隔离）、部署边界上差异显著；
- 独立后可单独做**安全加固与等保合规**、独立授权、独立部署，将外部访问面与内部主数据系统物理/逻辑隔离，降低越权与数据泄露风险；
- 门户数据以「只读快照 + 申请通道」为主，不持有客户/商机主数据实体，独立归属更清晰。

### 0.2 本系统 V1.0 范围

| 模块 | 功能编号 | 说明 |
|---|---|---|
| 门户访问控制 | CP-001 客户门户访问控制 | 链接入口、、登录、账号安全（含 PO-08） |
| 项目透明化 | CP-002 项目进度查询 | 项目列表、项目详情（阶段进度、时间线、动态、团队、延期预警） |
| 报告自助 | CP-003 电子报告申请与发放 | 申请通道、审批触发（下游）、加密发放、下载留痕 |
| 合规自助 | CUS-004 备案信息填写 | 等保备案 7 步向导、实时校验、暂存、生成备案材料 |
| 服务反馈 | CP-004 客户反馈与服务评价 | 服务评价（4 维度星级 + 评语）、客户反馈（异议/投诉/建议） |

### 0.3 范围变更影响点

1. **客户身份与账号开通**：门户账号不自行创建客户，账号开通动作（"开通门户"）仍由**客户与商机管理子系统**在客户档案中发起（见 §7），门户只消费其下发的凭证并完成登录验证。
2. **项目数据来源**：门户 CP-002 展示的项目进度、里程碑、动态均为**下游项目服务管理子系统的只读快照**（延迟 ≤5 分钟），门户不管理项目执行。
3. **报告发放链路**：门户 CP-003 仅做「申请通道 + 发放通道」，报告文件生成、审批由**下游项目服务管理子系统**完成；本系统不生成报告本身。
4. **客户主数据**：门户展示的个性化信息（如"欢迎回来，华兴证券"）来自**客户与商机子系统 PULL 的客户档案摘要**，门户不维护客户主数据实体。
5. **页面清单**：门户端 PO-01~PO-08 整体归属本系统；管理端（客户与商机子系统）不再承载任何门户页面（见《客户与商机管理子系统 前端页面清单 V2.0》修订）。

## 1. 问题陈述（Problem Statement）

测评业务的客户（业主/三方/政府/事业单位）在合同签订后的**交付与服务阶段**，缺乏透明、自助的官方渠道了解项目进度、获取测评报告、完成等保备案。当前依赖人工沟通（电话、邮件、微信），造成：

- 客户反复追问进度，抬高交付团队的沟通负荷，挤压专业服务时间；
- 电子报告传递靠邮件附件，缺乏加密与留痕，存在数据泄露与合规风险；
- 等保备案信息由人工收集填写，效率低、易错、客户体验差；
- 服务结束后缺乏结构化反馈与评价通道，服务质量改进无数据支撑。

**不解决的成本**：交付团队陷入低价值沟通、客户满意度下降影响复购、报告传递合规风险、备案返工成本。

## 2. 目标（Goals）

| # | 目标 | 类型 | 衡量方式 |
|---|---|---|---|
| G1 | 客户自助查询覆盖主要进度/报告类诉求，降低人工沟通量 | 业务 | 门户功能使用率、对应工单量下降比例 |
| G2 | 电子报告申请与发放全程加密留痕，零明文泄露 | 合规 | 报告发放审计完整率、异常下载冻结率 |
| G3 | 等保备案信息客户自助填写，减少人工收集返工 | 业务 | 备案自助提交占比、平均填表时长 |
| G4 | 服务反馈与评价结构化沉淀，驱动服务质量改进 | 业务 | 评价提交率、低分闭环率 |
| G5 | 门户访问安全合规，越权/异常访问可控 | 合规 | 异常登录拦截率、账号安全事件数 |

## 3. 非目标（Non-Goals）

1. **客户主数据维护**——客户档案由客户与商机管理子系统维护，门户只消费摘要、不编辑主数据。
2. **商机/报价/投标管理**——属于客户与商机子系统、报价与投标子系统，门户不直接管理（见 §7 开放问题 Q1）。
3. **项目执行管理**——项目进度来自下游快照，门户不管理项目执行。
4. **报告文件生成**——报告由下游项目服务子系统生成，门户只做申请与发放通道。
5. **IM/邮件/短信三方集成**——本期不实施，通知降级为站内消息，字段预留扩展位。
6. **移动端 / 响应式适配**——本期按桌面端布局，移动端不在范围内（P2 候选）。
7. **门户自注册**——门户**不提供自注册入口**；账号由**客户与商机管理子系统**在「生成注册链接（CM-004）」时**同步创建**（默认用户名 = 客户登记联系人手机号、初始口令 11223344、首次登录强制改密），门户仅消费该账号并完成首次登录激活（见 §5.1 / §7）。

## 4. 用户故事（User Stories）

- 作为**客户联系人**，我希望通过客户与商机系统下发的**注册链接**在门户完成首次登录激活（初始口令 11223344，登录后立即修改），以便自助查看我的项目与报告。
- 作为**客户联系人**，我希望在线查看项目实时进度与关键节点（含里程碑、动态），以便减少对交付团队的进度追问。
- 作为**客户联系人**，我希望在线申请并下载加密电子报告，以便及时、安全地获取测评结果。
- 作为**客户联系人**，我希望在线填写等保备案信息并生成备案材料，以便高效完成合规手续、减少返工。
- 作为**客户联系人**，我希望对项目服务进行评价并提交反馈（异议/投诉/建议），以便表达诉求并推动改进。
- 作为**客户 IT 管理员**，我希望管理门户账号安全（查看登录记录、口令强度、修改口令），以便保障门户访问安全。

### 5.6 优先级说明
- **P0（Must）**：CP-001/PO-08、CP-002、CP-003 —— 安全登录 + 进度透明 + 报告自助，构成门户核心价值。
- **P1（Should）**：CUS-004 备案、CP-004 评价与反馈 —— 重要自助能力，建议首版同步交付。
- **P2（未来）**：门户消息中心聚合、移动端适配、反馈与工单系统联动、报告在线预览 —— 本期不建，数据模型预留。

## 6. 成功指标（Success Metrics）

### 领先指标（上线后数周内）
- 门户注册激活率（收到邀请码后 7 日内激活）≥ 70%
- 门户各功能使用率（项目进度查询 / 报告申请 / 备案 / 评价）逐周上升
- 异常登录拦截率 ≥ 99%；账号安全事件（口令爆破、异常 IP）可观测

### 滞后指标（上线后 1–2 季度）
- 客户人工进度/报告类咨询工单下降 ≥ 30%
- 客户满意度（NPS）提升 ≥ 5 分
- 服务评价提交率（项目完成后）≥ 60%
- 备案信息自助提交占比 ≥ 50%，平均填表时长下降 ≥ 40%
- 报告明文外发事件 = 0

### 测量方法
- 埋点：门户登录/登出事件、各功能访问事件、报告申请/下载事件、备案提交事件、评价提交事件
- 报表：门户使用周报、报告发放审计月报、服务评价月度分析

### 7.1 关键接口契约（概要）

| 接口 | 方向 | 说明 | 触发时机 |
|---|---|---|---|
| 创建门户账号（开通+注册链接） | 上游 → 门户 | 客户与商机系统「生成注册链接（CM-004）」时调用：传 customerId、loginName（登记联系人手机号）、初始口令 11223344、forcePwdChange=true，门户创建账号返回 accountId | 客户档案生成注册链接 |
| **注册链接校验** | **门户 → 上游** | 门户首次登录/激活页调用：传 token，上游校验有效性（存在/未过期/未撤销/未使用）返回 customerId、loginName、phone；无效拒绝激活 | 客户点击注册链接进入门户激活页 |
| 查询客户档案摘要 | 门户 ← 上游 | 返回客户名称、行业等展示用摘要 | 门户登录后个性化展示 |
| 查询项目快照 | 门户 ← 下游 | 返回该客户关联项目的进度、里程碑、动态、团队 | 项目列表/详情加载 |
| 提交报告申请 | 门户 → 下游 | 传项目/报告类型/邮箱，触发下游审批与发放 | 门户 CP-003 提交申请 |
| 查询报告发放状态 | 门户 ← 下游 | 返回申请审批状态、加密下载链接与有效期 | 报告中心记录刷新 |

> 详细字段级契约以《跨子系统集成契约 T5》为准，本表仅界定责任边界。
