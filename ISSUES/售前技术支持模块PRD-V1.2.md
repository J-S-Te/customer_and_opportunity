## 0. 模块定位与范围（基于反馈收敛）

本模块是客户与商机管理子系统内的**新增轻量模块「售前技术支持（TS）」**，管理售前技术支持的**申请—审批—指派—执行—工时**工作流。它解决的是"派工靠电话、过程不可见、工时难统计"的问题，是协调层，不是文档层。

**关键收敛结论（来自调研与决策反馈）：**

| 来源 | 结论 | 对本 PRD 的影响 |
|---|---|---|
| R1 / D5 | 流程：销售发起 → 销售总监审批 → 团队负责人审批 → 团队负责人指派实施工程师 → 实施工程师技术支持 | 定义 TS-001~TS-005 流程与角色 |
| R2 / D6 | 方案不纳入系统管理（中间材料，不集中保存） | Non-goal #1；不设计文档存储 |
| R3 | 现状无准确统计口径，难以量化 | 成功指标以"线上化/覆盖率"为主，先建基线 |
| R4 | 全部技术人员均可参与：技术总监、团队负责人、项目经理、实施工程师 | 指派人员池 = 全体技术人员 |
| D1 | 仅"派工+过程记录"最小集 | 不做知识库/模板库/POC |
| D2 | 方案制定阶段产出（技术方案）在报价与投标子系统以"技术标"产生 | 本模块不承载技术标产物 |
| D3 | 不强制驱动商机阶段（方案多次修订，人工驱动） | 不新增阶段驱动回写 |
| D4 | 售前工时须输入项目管理系统的时间计划 | 新增 CRM→项目管理系统 工时推送（数据流 K） |
| D7 | 不作为（不向项目服务推送交付输入） | Non-goal #6 |

## 1. 问题陈述（Problem Statement）

**现状（来自 R1 / R3）：**
- 派工靠各相关人员电话沟通协调，无系统记录；
- 售前过程不可见，销售看不到进度，技术负责人无法掌握团队售前负载；
- 工时散落在个人处，无法汇总统计，无量化基线。

**痛点：**
- 派工无留痕，人员冲突/遗漏难发现，权责不清；
- 销售对客户承诺时无法掌握售前实际进度；
- 技术负责人无法做售前资源规划（没人、没数）；
- 工时无法汇总，项目管理系统时间计划缺售前投入数据；
- 审计、复盘、绩效无据。

**不解决的成本：** 售前资源浪费与冲突、商机因技术支持不及时而流失、管理盲区持续。

## 2. 目标（Goals）

| # | 目标 | 类型 | 衡量方式 |
|---|---|---|---|
| G1 | 售前派工线上化，告别电话协调 | 业务 | 申请线上发起率 ≥ 95%（上线后 1 季度） |
| G2 | 两级审批时效可见、超时可预警 | 用户+业务 | 审批平均时长、超时提醒触达率 |
| G3 | 售前过程对销售/技术负责人实时可见 | 用户 | 任务状态可视化覆盖率 100% |
| G4 | 工时闭环：登记并成功推送项目管理系统 | 业务 | 工时登记覆盖率 ≥ 90%，推送成功率 ≥ 99% |
| G5 | 建立售前投入基线（解决 R3 无口径问题） | 业务 | 售前投入报表可用（月度） |

> 注：因 R3 当前无历史基线，**本期目标以"线上化率/覆盖率/推送成功率"为主**；转化率等经营指标待基线建立后于下一周期设定，不凭空定目标。

## 3. 非目标（Non-Goals）

1. **不管理方案/技术标文档本身**（D6 / R2）——技术方案在报价与投标子系统以"技术标"产生。
2. **不强制驱动商机阶段推进**（D3）——任务完成由人工推进商机。
3. **不替代项目管理系统的时间计划**——仅推送工时（D4）。
4. **不承载技术标产物**（D2，归报价与投标子系统）。
5. **不做知识库 / 模板库 / POC 管理**（最小集 D1）。
6. **不向项目服务子系统推送售前方案作为交付输入**（D7）。
7. **不内置 IM/邮件/短信**——通知降级站内（沿用 CRM V2.0）。
8. **不管理项目执行、不生成合同**（沿用既有边界）。

## 4. 用户故事（User Stories）

- 作为**销售人员**，我希望从商机详情一键发起售前技术支持申请并关联该商机，以便需求有上下文、全程可追踪。
- 作为**销售人员**，我希望实时查看我发起的售前任务状态与进度，以便在向客户承诺时心中有数。
- 作为**销售总监**，我希望审批售前申请并留痕，以便资源使用可控、合规。
- 作为**团队负责人**，我希望审批后从技术人员池中指派合适人员，并在冲突时改派，以便快速响应。
- 作为**实施工程师（技术人员）**，我希望更新执行进度、登记实际工时，以便工作被记录且工时进入项目管理系统。
- 作为**技术负责人/管理层**，我希望看到团队售前负载与投入统计，以便做资源规划（后续报表）。

## 7. 跨子系统边界（更新）

| 外部系统 | 关系 | 本模块边界 |
|---|---|---|
| 商机（本系统内） | 上游 | 申请强制关联商机；商机详情只读展示关联任务；**不驱动商机阶段**(D3) |
| 报价与投标子系统 | 无接口 | 本模块不交互文档；技术方案产物在其「技术标」(D2)，本模块仅协调 |
| **项目管理系统** | **新增双向** | **下游**（CRM→PMS 工时推送 K，TS-006）；**上游**（PMS→CRM 人员主数据同步 J，支撑 TS-003 指派人员池） |
| 项目服务子系统 | 无 | 不推送售前方案作为交付输入（D7） |
| 合同 / 门户 / IM | 无 / 沿用 | 无关；通知降级站内 |

> **系统区分**：本文档的「项目管理系统（PMS）」指承载技术/实施人员主数据与项目时间计划的系统，与既有「项目服务子系统（PRJ，负责进度快照/报告审批，见 T5 D/E/F）」为不同系统。售前工时推送与人员同步均对接 PMS，不对接 PRJ。

### 7.1 新增数据流 K：售前工时推送（CRM → 项目管理系统）【已定义】

> Q1 决议：接口由产品方定义。本流将已登记的售前工时推送至项目管理系统的「时间计划」，供其统计资源投入。T5 此前无 CRM→项目管理系统推送流，本流为新增契约（详见 T5 §K）。

- **Topic**：`crm.presale.worklog.created`
- **方向**：本系统 → 项目管理系统
- **通道**：MQ 异步（至少一次），下游按 `idempotencyKey` 去重
- **触发**：工时提交（TS-005 提交触发 TS-006）
- **幂等键**：`taskId + personId + workDate`
- **字段级契约（K）**

| 字段 | 类型 | 必填 | 约束 / 说明 |
|---|---|---|---|
| eventType | string | 是 | 固定 `PRESALE_WORKLOG_CREATED` |
| taskId | string | 是 | 售前任务号（TS request_id） |
| opportunityId | string | 是 | 关联商机主键（溯源） |
| opportunityName | string | 否 | 商机名称（冗余便于核对） |
| personId | string | 是 | 实施人员主键，**取自数据流 J 同步的 PMS 人员主数据**，PMS 可直接匹配 |
| implementerDept | string | 是 | **实施人员部门** ← Q1 指定字段 |
| personName | string | 是 | **姓名** ← Q1 指定字段 |
| workStartTime | datetime | 是 | **起止时间·开始** ← Q1 指定字段，格式 `yyyy-MM-dd HH:mm:ss` |
| workEndTime | datetime | 是 | **起止时间·结束** ← Q1 指定字段 |
| unit | enum | 是 | **标准化推送单位：`小时`**（Q5 决议：PMS 口径=小时，基准单位小时；登记可选「人天」，提交时按 `1 人天 = 8 小时` 换算为 `workHours` 小时值，系数可配置；原始登记口径存 `raw_unit`/`raw_hours` 供审计；已与 PMS 书面确认） |
| workHours | decimal | 是 | 工时数值（按 unit 计，基准为小时），用于时间计划统计 |
| workSiteAddress | string | 是 | **地址**：工作地点（客户现场/远程等）← Q1 指定字段 |
| venue | enum | 是 | **场地类型**（现场/远程），取自申请层 `t_ts_request.venue`，PMS 资源排期可区分现场/远程 |
| workContent | enum | 否 | **工作内容**（方案设计/技术交流/POC演示/技术答疑/其他），执行时记录（原「技术支持类型」由申请层移至工时层，避免与场地类型概念混淆） |
| idempotencyKey | string | 是 | `taskId + '-' + personId + '-' + workDate` |
| rawUnit | enum | 否 | 原始登记单位（人天/小时），换算前口径，供审计溯源 |
| rawHours | decimal | 否 | 原始登记工时数值（按 rawUnit 计） |

> **Q5 决议（工时单位口径，2026-07-29 已确认）**：经与 PMS 书面确认，项目管理系统时间计划以「小时」为统计口径，故**统一以小时为推送基准单位**（含小数，如 0.5 小时）。登记界面允许选「人天」或「小时」，提交时系统按 `1 人天 = 8 小时`（组织可配置）自动换算为 `workHours` 小时值后再推送；原始登记单位/数值保留于 `raw_unit`/`raw_hours` 供审计。契约 K 中 `unit` 默认值由「人天」切换为「小时」，换算方向相应反转，契约影响面小。

### 7.2 新增数据流 J：技术/实施人员主数据同步（项目管理系统 → CRM）【Q2 决议】

> Q2 决议：技术人员池主数据从项目管理系统同步。本流将 PMS 中的技术/实施人员（含部门、角色、技能、在职状态）同步至 CRM，作为 TS-003 指派的人员池来源。T5 此前无 PMS→CRM 同步流，本流为新增契约（详见 T5 §J）。

- **方向**：项目管理系统 → 本系统
- **通道**：定时拉取（Feign，建议每 6 小时）+ 手动刷新（TS-003 指派页「刷新人员池」）
- **接口**：`GET /api/v1/pms/technicians?scope=tech`
- **写入**：`t_ts_engineer_pool`（覆盖式 upsert by personId）
- **字段级契约（J）**

| 字段 | 类型 | 必填 | 约束 / 说明 |
|---|---|---|---|
| personId | string | 是 | PMS 人员主键（权威），本系统不另建军号；工时推送 K 回写即引用此 ID |
| personName | string | 是 | 姓名 |
| department | string | 是 | 部门（与工时推送 implementerDept 一致） |
| role | enum | 是 | 技术总监 / 团队负责人 / 项目经理 / 实施工程师（R4：全体技术人员可参与） |
| skillTags | string[] | 否 | 技能标签，辅助指派 |
| contact | string | 否 | 联系方式（用于指派通知） |
| validFlag | bool | 是 | 是否在职可指派 |
| syncedAt | datetime | 是 | 同步时间 |

```json
{
  "technicians": [
    {
      "personId": "PMS-U10086",
      "personName": "王建国",
      "department": "安全技术部",
      "role": "实施工程师",
      "skillTags": ["等保", "云计算安全"],
      "contact": "138****0000",
      "validFlag": true,
      "syncedAt": "2026-07-23 08:00:00"
    }
  ]
}
```

> 指派时仅展示 `validFlag=true` 人员；人员重名以 personId 区分；personId 停用/变更由下次同步自动生效。

## 8. 数据模型（轻量）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `t_ts_request` | request_id(TS+YYYYMMDD+4)、opportunity_id、applicant_id、venue(现场/远程)、service_address(现场必填)、contact_name、contact_phone、description、expect_start、expect_end、urgency、status、reject_reason、created_at | 售前申请主表（场地类型+对接联系人，供实施人员对接） |

| `t_ts_assignment` | assign_id、request_id、assignee_id、assignee_role、assigned_by、assigned_at、is_current | 指派记录（支持改派历史） |
| `t_ts_worklog` | log_id、request_id、person_id、work_hours、work_date、work_start、work_end、unit、raw_unit、raw_hours、work_site_address、created_at、idempotency_key | 工时记录（推送项目管理系统，字段对齐数据流 K；unit 为标准小时、raw_unit/raw_hours 为原始登记口径供审计） |
| `t_ts_engineer_pool` | person_id、person_name、department、role、skill_tags、contact、valid_flag、synced_at | 技术/实施人员池（数据流 J 同步自项目管理系统） |

**关联**：`opportunity_id` → `t_business_opportunity`；`person_id` → `t_ts_engineer_pool`（取自数据流 J 同步的 PMS 人员主数据，PMS 权威）。
