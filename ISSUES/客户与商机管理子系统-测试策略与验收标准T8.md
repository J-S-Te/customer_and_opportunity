## 一、测试策略总览

### 1.1 测试金字塔（投入占比）

```
        /\        E2E（管理端关键链路）        ~10%
       /  \       ------------------------------
      /----\       跨子系统集成（Mock 下游）    ~15%
     /------\      API 契约测试（完整 T4）       ~25%
    /--------\     集成测试（DB/GORM）          ~20%
   /----------\    单元测试（Go testing）        ~30%
  /------------\
```

原则：**左移**（需求/契约先行）、**自动化优先**（单测/接口可 CI 回归）、**契约即文档**（API 契约作为接口测试基线）。

> 注（待确认事项 5）：本系统 E2E **先覆盖管理端关键链路自动化**（客户建档/查重、商机 7 阶段看板/阶段推进/转合同/关联合同/失败原因、跨子系统跳转报价与投标、客户详情「生成注册链接（CM-004）」）；其余路径以**手工测试**覆盖。门户端 E2E 由《客户自助门户子系统 T8》负责。

### 1.2 测试类型与覆盖目标

| 类型 | 目标覆盖 | 自动化 |
|---|---|---|
| 单元测试 | 核心业务逻辑（编号生成、字段加密、审批流转、**阶段状态机/终态校验 R1~R4**、独立重开审批） | 必须 CI |
| 集成测试 | 服务 + DB（GORM 真实库） | 必须 CI |
| API 契约测试 | **完整 T4 请求/响应 schema（含门户/报价/投标接口，由对应子系统协同覆盖）** | 必须 CI |
| 跨子系统集成 | T5 V2.1 的 A/D/G/H/I/L/J/K/M/N（Mock 下游/门户） | 必须 CI |
| 前端 E2E | **管理端关键流自动化，其余手工**（见 §1.1 注） | 关键路径 |
| 安全测试 | 等保 checklist + 渗透（OWASP Top 10），**仅本系统控制点** | 上线前 |
| 性能测试 | T2 性能指标 + **≥200 TPS 写基线（合成数据）** | 上线前 |
| 兼容性 | 浏览器矩阵（Chrome/Edge/飞书内嵌） | 抽样 |
