## 0. 拆分与范围变更说明

### 0.1 拆分决策

将《需求说明书 V1.2》中的以下功能模块从本系统剥离：

- **BM-003 报价单管理与审批**、**BM-004 投标管理** → 独立组建 **「报价与投标管理子系统 V1.0」**（见独立 PRD）；
- **客户自助门户（CP-001 客户门户访问控制、CP-002 项目进度查询、CP-003 电子报告申请与发放、CUS-004 备案信息填写、CP-004 客户反馈与服务评价）** → 独立组建 **「客户自助门户子系统 V1.0」**（见独立 PRD）。

决策依据：
- 报价与投标是围绕「商务竞争动作」的专业闭环，参与角色、合规要求（保证金、限价审批、开标）与企业日常客户经营差异显著；
- 门户服务对象是外部客户，安全合规要求（HTTPS、审计、权限隔离）与内部经营系统差异显著，独立部署可隔离外部访问面、降低越权风险；
- 独立后可分别排期、授权、对接下游系统，降低本系统（客户主数据 + 商机经营）的复杂度。

### 0.2 本系统 V2.0 保留范围

| 模块 | 功能编号 | 说明 |
|---|---|---|
| 客户主数据管理 | CM-001 客户信息录入与维护 | 完整保留 |
| | CM-002 客户信息查询与检索 | 完整保留 |
| | CM-004 门户账号开通与注册链接生成 | 新增（见 §5.1 / §7）：客户详情一键生成 2h 有效注册链接，并同步为登记联系人创建门户账号 |
| 商机跟进管理 | BM-001 商机创建与信息维护 | 保留，但「生成报价」「发起投标」动作改为跨子系统调起 |
| | BM-002 商机跟进与阶段推进 | 保留，阶段名称保留「报价/投标」但执行在外部子系统 |

### 0.3 范围变更影响点

1. **商机阶段「报价 / 投标」**：保留为销售管线阶段名称（商机仍需走到这两个阶段以反映销售进度），但**实际报价单编制、投标执行**在「报价与投标管理子系统」完成；商机详情页不再内置报价/投标编辑，改为**跨子系统跳转/调起**并展示关联报价/投标的只读状态。
2. **商机预计金额校验**：升级为**跨子系统接口**——本系统在商机签单前，向报价与投标子系统查询该商机「最新已通过报价单」金额进行一致性比对（见 §7.2）。
3. **审批节点矩阵**：原 V1.2 附录 B 中「报价单提交 / 低于限价报价」两项转移至报价与投标子系统；「报告申请」由门户发起、下游审批；本系统保留「商机阶段推进 / 商机作废 / 门户账号开通（触发）」审批（原「信用等级调整」审批随 CM-003 删除而移除）。
4. **数据保留策略**：原 V1.2 附录 A 中「报价单 / 投标项目」「门户登录日志 / 报告发放记录 / 客户反馈与评价」转移至对应子系统；本系统保留客户档案、商机档案、客户操作日志、客户沟通记录等保留策略。
5. **页面清单**：管理端 P-03/P-07（报价）、P-04/P-08（投标）整体迁移至报价与投标子系统；门户端 PO-01~PO-08 整体迁移至客户自助门户子系统；本系统页面清单见《客户与商机管理子系统 前端页面清单 V2.0》（仅含管理端 4 页）。
6. **门户模块剥离**：原 CP-001~004、CUS-004 整体迁移至《客户自助门户子系统 PRD V1.0》。本系统不再承载门户端页面与门户账号体系；客户「开通门户」动作仍在本系统客户档案发起，但登录与门户功能由门户子系统承载。
7. **CM-004 门户账号开通与注册链接生成（新增）**：将原「开通门户」动作具体化——销售在客户详情点击「生成注册链接」，系统**同步调用门户子系统创建门户账号**（默认用户名 = 客户登记联系人手机号、初始口令固定 `11223344`、首次登录强制改密），并生成本系统持有的**注册链接（token，2 小时有效）**；客户点击链接在门户首次登录后须修改口令方可使用。门户子系统**不提供自注册入口**（见门户 PRD V1.0 §3）。详见 §5.1 / §7。

### 0.4 V2.1 商机状态管理补丁（2026-07-27）

将商机阶段**终态化**：`current_stage` 由 5 个推进阶段扩展为「5 推进 + 已签约 / 失败」共 7 值；`opp_status` 精简为 跟进中 / 已关闭 / 已作废；**已签约必选关联合同（合同管理子系统）、失败必填原因**；「报价 / 投标」阶段开放人工编辑，与回传协同。看板由 5 列变 7 列。详细变更、校验规则、跨系统接口与验收标准见《客户与商机管理子系统-商机状态管理需求更新-V2.1.md》。

## 1. 问题陈述（Problem Statement）

客户与商机管理子系统承载测评业务**合同签订前**的客户经营与商机培育全流程。销售团队需要在统一平台上维护客户主数据、培育并跟进商机。

**痛点**：
- 客户信息分散、口径不一，销售交接与数据分析时难以追溯；
- 商机跟进缺乏可视化阶段管理，销售转化过程不可见、不可预测；
- （客户自助透明渠道的痛点已随门户模块独立至《客户自助门户子系统 PRD V1.0》，本系统聚焦内部客户经营与商机培育）

**不解决的成本**：客户信息失真导致报价/交付偏差；商机流失无预警造成收入损失。（客户自助能力缺失的成本由门户子系统承接）

## 2. 目标（Goals）

| # | 目标 | 类型 | 衡量方式 |
|---|---|---|---|
| G1 | 客户主数据准确率显著提升，重复客户率下降 | 业务 | 查重命中率、客户档案完整度评分（上线后 1 季度） |
| G2 | 商机阶段可视化覆盖率 100%，阶段停留超时自动预警 | 用户+业务 | 看板阶段分布、超时预警触发率 |
| G3 | 商机转化率可量化追踪（从初步接触到已签约） | 业务 | 各阶段转化率漏斗（月度，含输单率） |
| G4 | 报价/投标动作顺畅衔接，商机→报价/投标→合同链路不中断 | 业务 | 跨子系统跳转成功率、商机「报价/投标」阶段关联率 |
| G5 | 与门户子系统顺畅衔接，客户身份/账号开通驱动门户自助服务 | 业务 | 客户档案「开通门户」触发率、门户账号激活率（指标归属门户子系统） |

## 3. 非目标（Non-Goals）

1. **报价单管理与审批（BM-003）**——已剥离至「报价与投标管理子系统 V1.0」，本系统不再实现报价编制、审批、版本管理。
2. **投标管理（BM-004）**——已剥离，本系统不再实现标书、保证金、开标、中标/落标处理。
3. **客户自助门户（CP-001~004、CUS-004）**——已独立为「客户自助门户子系统 V1.0」，本系统不再实现门户登录、项目进度查询、报告申请、备案填写、服务评价等外部客户功能。
4. **合同生成与管理**——本系统只「推送」商机/签单数据至合同管理子系统，**不生成合同草稿**（沿用 V1.2 边界）。
5. **项目执行管理**——本系统只「拉取」项目服务子系统快照，**不管理项目执行**。
6. **IM/邮件/短信三方集成**——本期不实施，所有通知降级为站内消息，字段保留扩展位（沿用 V1.2）。
7. **移动端 / 响应式适配**——本期按桌面端布局，移动端不在范围内。

## 4. 用户故事（User Stories）

### 客户主数据
- 作为**销售代表**，我希望在统一入口录入客户的全维度档案（基础/业务/干系人/信息系统/财务），以便后续商机和交付都能复用同一份主数据。
- 作为**销售代表**，我希望新建客户时系统自动查重（名称模糊 + 信用代码精确），以免产生重复客户档案。
- 作为**系统管理员**，我希望客户合并时保留历史商机关联，以便组织调整或录入错误时安全归并。
- 作为**销售代表**，我希望在客户详情一键「生成注册链接」（2 小时有效），系统同步为客户登记联系人创建门户账号（默认用户名 = 联系人手机号、初始口令 11223344、首次登录强制改密），以便客户快速、安全地接入自助门户。

### 商机跟进
- 作为**销售代表**，我希望从客户详情一键发起商机，系统带入客户信息，以便快速启动跟进。
- 作为**销售代表**，我希望用看板拖拽推进商机阶段并补充跟进记录，以便可视化管理我的销售管道。
- 作为**销售代表**，当商机进入「报价」「投标」阶段时，我希望一键调起报价与投标子系统并自动关联本商机，以便商务动作顺畅衔接且不丢失上下文。
- 作为**销售总监**，我希望关键阶段推进（必经审批）和商机作废经过审批留痕，以便销售过程合规可控。
- 作为**销售代表**，我希望商机签单后一键「转合同」推送至合同管理子系统，以便下游无缝生成合同草稿。
- 作为**系统**，我希望在签单前核验该商机最新已通过报价金额与商机预计金额的一致性，以便商务口径不脱节（跨子系统）。
- 作为**销售/客户成功**，我希望在客户档案「开通门户」时触发门户账号开通，以便客户顺畅接入自助门户（跨子系统）。

## 6. 成功指标（Success Metrics）

### 领先指标（上线后数周内）
- 客户主数据完整度（必填字段填充率）≥ 90%
- 商机看板阶段分布可视化覆盖率 100%，超时预警触达率 ≥ 95%
- 跨子系统「生成报价/投标」跳转成功率 ≥ 99%
- （门户注册激活率、门户功能使用率等指标归属《客户自助门户子系统 PRD V1.0》）

### 滞后指标（上线后 1–2 季度）
- 商机整体转化率（初步接触→签单）提升 ≥ 10 个百分点
- 商机「报价/投标」阶段关联率（进入该阶段即有关联报价/投标）≥ 90%
- （客户人工咨询工单下降、NPS 等门户相关指标归属《客户自助门户子系统 PRD V1.0》）

### 测量方法
- 埋点：客户档案编辑完成事件、商机阶段变更事件、跨子系统跳转事件（门户/报价与投标）
- 报表：销售漏斗报表（月度）、跨子系统调用监控（实时）

| **客户自助门户子系统**（新） | 同项目同步建设 | 本系统**提供接口**供其查询客户档案摘要用于门户个性化；本系统在客户档案「生成注册链接（CM-004）」时**同步创建门户账号**并持有注册链接（token）；门户**不提供自注册**，登录态由本系统创建账号 + 链接校验驱动；本系统不实现门户端功能（登录/项目进度/报告/备案/评价） |

| 项目服务管理子系统 | 同项目同步建设 | 本系统只**拉取**项目快照，**不管理项目执行**（沿用） |
| IM/邮件/短信 | 本期不接 | 所有通知降级为站内消息，字段保留扩展位（沿用） |
| 通用审批引擎 | 待定 | 商机阶段推进/商机作废/门户账号开通走审批引擎实例化（沿用） |

### 7.1 与兄弟子系统的关键接口契约（概要）

| 接口 | 方向 | 说明 | 触发时机 |
|---|---|---|---|
| 调起新建报价 | 本系统 → 报价与投标 | 传商机 ID、客户 ID、需求摘要，在其系统内创建报价单草稿 | 商机详情「生成报价」 |
| 调起新建投标 | 本系统 → 报价与投标 | 传商机 ID、客户 ID、招标摘要 | 商机详情「发起投标」 |
| 查询关联报价/投标状态 | 本系统 ← 报价与投标 | 返回该商机下最新报价/投标的状态、金额、关键时间（详情加载时 PULL 快照） | 商机详情加载、阶段联动展示 |
| **报价/投标状态变更回写（推送）** | 本系统 ← 报价与投标 | 报价/投标**创建完成或状态变更**时，向本系统推送该商机的状态（报价：审批中/已通过/已失效；投标：标书制作/开标中/中标/落标），用于驱动商机「报价/投标」阶段的进展 | 报价单提交审批、报价审批结果、投标创建、开标结果、中标/落标 |
| 查询已通过报价金额 | 本系统 ← 报价与投标 | 返回该商机「最新已通过报价单」金额，供金额一致性校验 | 商机签单/阶段推进至报价前 |
| 创建门户账号（开通+注册链接） | 本系统 → 门户 | 客户档案「生成注册链接（CM-004）」时调用：传 customerId、loginName（登记联系人手机号）、初始口令 11223344、forcePwdChange=true，门户创建账号并返回 accountId | 客户详情「生成注册链接」 |
| 注册链接校验 | 门户 → 本系统 | 门户首次登录/激活页调用：传 token，本系统校验有效性（存在/未过期/未撤销/未使用）并返回 customerId、loginName、phone；无效则拒绝激活 | 客户点击注册链接进入门户激活页 |
| 查询客户档案摘要 | 门户 ← 本系统 | 返回客户名称、行业等展示用摘要 | 门户登录后个性化展示 |
| **查询合同列表/详情** | **本系统 ← 合同管理子系统** | **返回可选合同（contract_id、合同号、名称、金额、状态），供标记「已签约」时选择（V2.1 补丁 D2）** | **商机进入「已签约」或点击关联合同** |

> 详细字段级契约以《跨子系统集成契约 T5》为准，本表仅界定责任边界。

### 7.2 商机阶段与报价/投标状态映射（回传机制）

商机管线为 **5 个推进阶段 + 2 终态**：**初步接触 → 需求沟通 → 方案制定 → 报价 → 投标 →（已签约 / 失败）**。其中「报价」「投标」两个推进阶段的**实际执行状态由「报价与投标管理子系统」回传**，本系统同时开放人工编辑（回传 + 人工协同，见 V2.1 补丁 D3）。

回传的前提是**关联**：报价与投标子系统在创建报价单 / 投标项目时**必须关联一个商机**（携带商机 ID），以此建立状态回写的归属关系。创建完成或后续任何状态变更，均通过事件推送回本系统，驱动对应商机的阶段进展。

| 报价/投标子系统事件 | 回传状态 | 商机阶段响应 |
|---|---|---|
| 报价单创建并提交审批 | 报价审批中 | 维持「报价」阶段，标记回传状态 |
| 报价审批通过 | 报价已通过 | 允许推进至「投标」或签单 |
| 报价审批不通过 / 失效 | 报价已失效 | 回退至「方案制定」，标记流失风险 |
| 投标项目创建（标书制作/开标中） | 投标进行中 | 维持「投标」阶段 |
| 投标中标 | 中标 | 商机推进至「已签约」（终态）；若回传携带 contract_id 自动关联，否则置「待关联合同」提示，待人工选择（受关联合同必填约束） |
| 投标落标 | 落标 | 商机推进至「失败」（终态）；若回传含落标原因带入 lost_reason，否则人工补填（受失败原因必填约束） |

**回写字段范围（决策）**：状态为**必回写**字段（直接驱动商机阶段）；金额、关键时间作为**可选辅助回写**，用于金额一致性校验与商机详情展示（见开放问题 Q3）。
